# SA1514: 元素文档标头之前应有空行

## 原因

C# 元素上方的元素文档标头之前没有空行。

## 规则说明

为了提高代码的可读性，StyleCop 在某些情况下要求空行，在其他情况下禁止空行。
这样会在代码中形成一致的视觉模式，使不熟悉的代码也更容易识别和阅读。

当元素上方的元素文档标头之前没有空行时，会违反此规则。
例如：

```csharp
public bool Visible
{
    get { return this.visible; }
}
/// <summary>
/// Gets a value indicating whether the control is enabled.
/// </summary>
public bool Enabled
{
    get { return this.enabled; }
}
```

上述代码会产生一处违规，因为文档标头之前没有空行。

此规则的一个例外是文档标头位于其作用域中的第一项的情况。
此时，标头之前不应有空行。
例如：

```csharp
public class Class1
{
    /// <summary>
    /// Gets a value indicating whether the control is enabled.
    /// </summary>
    public bool Enabled
    {
        get { return this.enabled; }
    }
}
```

在上述代码中，标头是其作用域中的第一项，因此其前面不应有空行。

## 如何修复违规

要修复此规则的违规情况，请在文档标头上方添加空行。

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.LayoutRules", "SA1514:ElementDocumentationHeaderMustBePrecededByBlankLine", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1514 // ElementDocumentationHeaderMustBePrecededByBlankLine
#pragma warning restore SA1514 // ElementDocumentationHeaderMustBePrecededByBlankLine
```
