# SA1100: 仅在当前类中存在实现时才使用 base 前缀调用

## 原因

调用继承自基类的成员时使用了 `base.` 前缀，但当前类没有重写或实现该成员。

## 规则说明

代码使用 `base.` 前缀调用基类成员，但当前类没有该成员的实现时，会违反此规则。
例如：

```csharp
string name = base.JoinName("John", "Doe");
```

此规则旨在防止一种潜在的错误来源。
假设基类包含以下虚方法：

```csharp
public virtual string JoinName(string first, string last)
{
}
```

另一个类继承此基类，但没有在当前类中重写该方法。
此类中的某处通过 `base.JoinName(...)` 调用基类方法，此时行为符合预期。
后来，有人在此类中添加了该方法的重写：

```csharp
public override string JoinName(string first, string last)
{
    return "Bob";
}
```

此时，原有的 `base.JoinName(...)` 调用很可能导致代码错误。
它始终调用基类方法，从而忽略当前类中的重写。

因此，除非当前类实现了重写，并且开发者确实希望调用基类成员，否则不应在调用基类成员时使用 `base.` 前缀。
如果当前类没有重写基类成员，应使用 `this.` 前缀而不是 `base.`。

### 协变返回类型

从 C# 9 开始，重写成员可以返回比基类成员返回类型派生程度更高的类型。
即使中间类提供了协变实现，`base.` 调用仍会绕过派生程度最高的重写。
对于未声明自身重写的类中的 `base.` 调用，SA1100 仍会报告违规，建议的修复方式仍是改为通过 `this.` 调用成员。

## 如何修复违规

将 `base.` 前缀改为 `this.` 即可修复违规。

对于可继承类型中的可重写成员，不提供自动代码修复。
将 `base.` 改为 `this.` 可能会分派到子类中的重写，从而改变行为或引入无限递归。
诊断仍会报告；更改调用或抑制违规之前，请检查预期的分派行为。
对于非虚成员、密封重写以及密封类型中的调用，仍提供自动修复。

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.ReadabilityRules", "SA1100:DoNotPrefixCallsWithBaseUnlessLocalImplementationExists", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1100 // DoNotPrefixCallsWithBaseUnlessLocalImplementationExists
#pragma warning restore SA1100 // DoNotPrefixCallsWithBaseUnlessLocalImplementationExists
```
