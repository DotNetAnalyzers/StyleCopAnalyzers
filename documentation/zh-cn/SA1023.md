# SA1023: 取消引用和取址符号周围的空格应正确

## 原因

C# 元素中取消引用符号或取址符号周围的空格不正确。

## 规则说明

取消引用或取址符号周围的空格不正确时，会违反此规则。

符号周围的间距取决于它是否用于类型声明中。
如果用于类型声明，符号后应始终有一个空格，除非它是一行中的最后一个字符，或后面是左方括号或圆括号。
此外，符号前不应有空白字符，也不应是一行中的第一个字符。
以下示例展示了类型声明中间距正确的取消引用符号：

```csharp
object* x = null;
```

此规则也适用于函数指针声明。
在 `delegate* unmanaged[Cdecl]<int*, void>` 中，紧接 `delegate` 的 `*` 被视为类型声明的一部分，并遵循相同的间距规则。
省略调用约定时，`*` 应直接位于参数列表之前，例如 `delegate*<int*>`（`<` 前没有空格）。

取消引用或取址符号用于类型声明之外时，则遵循相反的规则。
此时，符号前应始终有一个空格，除非它是一行中的第一个字符，或前面是左方括号、圆括号或同类符号（如等号）。
符号后不应有空白字符，也不应是一行中的最后一个字符。
例如：

```csharp
y = *x;
```

## 如何修复违规

确保取消引用或取址符号周围的空格符合上述规则即可修复违规。

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.SpacingRules", "SA1023:DereferenceAndAccessOfMustBeSpacedCorrectly", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1023 // DereferenceAndAccessOfMustBeSpacedCorrectly
#pragma warning restore SA1023 // DereferenceAndAccessOfMustBeSpacedCorrectly
```
