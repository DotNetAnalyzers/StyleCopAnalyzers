# SA1415: 不要在内部类型的成员上使用 public

:bulb: 此规则默认情况下处于禁用状态。

## 原因

某个实际可访问性为内部或私有的类型的成员被声明为 `public`。

## 规则说明

当成员被声明为 `public`，但其包含类型在程序集外部不可见时，就会违反此规则。`internal` 或 `private` 类型的 `public` 成员并不属于程序集的公共 API，其可见性不会超过该类型本身。关注公共 API 变化的审阅者不得不额外排除这些成员。

此规则会报告类型的实际可访问性为 `internal`、`private` 或 `private protected` 时，成员上的显式 `public` 修饰符。这包括以下成员：

* 顶级 `internal` 类型的成员
* `private` 或 `internal` 嵌套类型的成员
* 嵌套在 `internal` 类型中、因而实际为内部的 `public` 或 `protected` 类型的成员
* `private protected` 嵌套类型的成员（包括嵌套在公共类型中的此类类型），这些类型在程序集外部不可见
* `file` 类型的成员

以下情况不会报告：

* 实际可访问性为 `public`、`protected` 或 `protected internal` 的类型的成员（这些成员可能在程序集外部可见）
* 实现接口或重写基成员的成员，这些成员必须保持为 `public`
* 语言要求必须为 `public` 的用户定义运算符和转换
* 接口成员（包括内部接口）以及枚举成员
* 未显式声明为 `public` 的成员，包括记录的隐式公共位置属性，例如 `internal record R(int Value)`
* 内部类型的 `protected` 或 `protected internal` 成员

此规则默认禁用，因为并非每个团队都将内部类型上的 `public` 视为问题。有些团队会在内部类型上使用 `public`，以标记以后打算提升为公共 API 的成员。

要启用此规则，请在 `.editorconfig` 文件中添加以下内容：

```ini
dotnet_diagnostic.SA1415.severity = warning
```

## 如何修复违规

将成员的可访问性从 `public` 改为 `internal`。对于在程序集外部不可见的类型的成员，两者是等效的，并且 `internal` 看起来不像公共 API 的一部分。

```csharp
internal class Example
{
    public void Method() // SA1415
    {
    }
}
```

```csharp
internal class Example
{
    internal void Method()
    {
    }
}
```

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.MaintainabilityRules", "SA1415:DoNotUsePublicOnMembersOfInternalTypes", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1415 // Do not use public on members of internal types
#pragma warning restore SA1415 // Do not use public on members of internal types
```
