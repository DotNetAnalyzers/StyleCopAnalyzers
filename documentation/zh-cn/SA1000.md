# SA1000: 关键字周围的空格应正确

## 原因

C# 关键字周围的空格不正确。

## 规则说明

关键字周围的空格不正确时，会违反此规则。

以下 C# 关键字后应始终有一个空格：`and`、`await`、`case`、`catch`、`fixed`、`for`、`foreach`、`from`、`group`、`if`、`in`、`is`、`into`、`join`、`let`、`lock`、`not`、`orderby`、`or`、`out`、`ref`、`return`、`scoped`、`select`、`switch`、`using`、`var`、`where`、`while`、`yield`。

`checked`、`default`、`nameof`、`sizeof`、`typeof` 和 `unchecked` 关键字后不应有空格，但以下情况除外：

* `default` 关键字用作 C# 7.1 的默认值字面量表达式时，后面可以有空格，也可以没有空格。

`new` 和 `stackalloc` 关键字后应始终有一个空格，但以下情况除外：

* `new` 或 `stackalloc` 关键字用于创建隐式类型数组时，关键字与数组左方括号之间不应有空格。
* `new` 关键字用于隐式对象创建（目标类型化的 new）时，关键字与左圆括号之间不应有空格。
* `new` 关键字用于泛型类型约束时，`new` 关键字与左圆括号之间不应有空格。

`throw` 关键字后应始终有一个空格，但重新引发异常的语句除外；此时 `throw` 关键字与分号之间不应有空格。

在 C# 9 的函数指针语法中，`delegate` 关键字与其后的 `*` 之间不得有空格，`unmanaged` 关键字与其后可选的调用约定列表之间也不得有空格。
例如，`delegate*<int, void>` 和 `delegate* unmanaged[Cdecl]<int, void>` 展示了此功能所要求的间距。

## 如何修复违规

根据上述说明，在关键字后添加或删除空格即可修复违规。

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.SpacingRules", "SA1000:KeywordsMustBeSpacedCorrectly", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1000 // KeywordsMustBeSpacedCorrectly
#pragma warning restore SA1000 // KeywordsMustBeSpacedCorrectly
```
