# SA1003: 符号周围的空格应正确

## 原因

C# 代码文件中运算符周围的空格不正确。

## 规则说明

运算符周围的空格不正确时，会违反此规则。

以下类型的运算符两侧应各有一个空格：冒号、算术运算符、赋值运算符、条件运算符、逻辑运算符、关系运算符、移位运算符以及 lambda 运算符。
例如：

```csharp
int x = 4 + y;
```

从 C# 8.0 开始，lambda 运算符 `=>` 也用于 switch 表达式臂。
相同的间距规则同样适用：每个箭头两侧都应各有一个空格。

```csharp
var description = value switch { 0 => "zero", _ => "nonzero" };
```

模式匹配表达式中的关系运算符位于 `is` 等关键字之后时，也遵循相同的规则。
例如，关系模式 `value is > 5` 中的 `>` 两侧必须有空格：`value is > 5`。
关系模式置于圆括号中时，`(` 后和 `)` 前仍不应紧邻空格，这与 SA1008 中说明的圆括号规则一致。

与此相反，一元运算符前应有一个空格，后面则不得有空格。
例如：

```csharp
bool x = !value;
```

符号前后为圆括号或其他括号时属于例外，此时符号与括号之间不应有空格。
例如：

```csharp
if (!value)
{
}
```

从 C# 8.0 开始，null 包容运算符（`!`）可以位于任何表达式之后的行尾。
下一个标记另起一行时，后缀递增和递减运算符（`++` 和 `--`）也可以位于行尾。
null 包容运算符与其后的元素访问之间也不应有空格。
例如：

```csharp
Print(
    value: nullableValue! // trailing comment
);

var result = nullableValue!
    .ToString();

var item = nullableArray![0];

var incrementedValue = GetCounter().Value++
    + 2;
```

C# 8 的*从末尾索引*运算符（`^`）遵循相同的一元运算符间距要求。
它应紧邻操作数，后面不加空格；紧接 `[` 或 `(` 时，也不应在这些标记后添加空格。
例如：

```csharp
var last = values[^1];
Index start = ^5;
```

C# 8 的*范围*运算符（`..`）被视为二元运算符，但两侧不应各留一个空格。
在索引器中，操作数之间应用此间距规则，同时 `[` 后和 `]` 前仍不添加空格。
例如：

```csharp
Range middle = 1..4;
var slice = values[1..^2];
```

## 如何修复违规

确保符号周围的空格符合上述规则即可修复违规。

构造函数初始值设定项的冒号位于行尾时，代码修复会将冒号与初始值设定项一起移到下一行，并保留其缩进：

```csharp
public MyType()
    : base(3)
{
}
```

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.SpacingRules", "SA1003:SymbolsMustBeSpacedCorrectly", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1003 // SymbolsMustBeSpacedCorrectly
#pragma warning restore SA1003 // SymbolsMustBeSpacedCorrectly
```
