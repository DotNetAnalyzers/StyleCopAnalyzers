# SA1605: 分部元素的文档注释应有摘要

## 原因

C# 代码元素的文档注释中的 `<summary>` 或 `<content>` 标记缺失或为空。

## 规则说明

C# 语法允许使用 XML 文档注释，直接在代码中为类和其他元素编写文档。
有关这些注释及其语法的介绍，请参阅：[https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments](https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments)。

如果分部元素（带有 partial 修饰符的元素）的文档注释缺少 `<summary>` 或 `<content>` 标记，或者这些标记为空，没有包含元素的说明，就会违反此规则。
在 C# 中，以下元素可以使用 partial 修饰符：类、方法、属性、索引器、构造函数和事件。

如果在分部类的多个部分中提供文档，这些部分的文档可能会合并为一份文档。
例如，考虑以下分部类的两个部分：

```csharp
/// <summary>
/// Documentation for the first part of Class1.
/// </summary>
public partial class Class1
{
}

/// <summary>
/// Documentation for the second part of Class1.
/// </summary>
public partial class Class1
{
}
```

同一分部类的这两个部分分别为类提供了不同的文档。
将该类的文档生成到 SDK 中时，文档生成工具可能只选择其中一部分而忽略其他部分；在某些情况下，也可能合并两份文档，形成类似这样的文本：“Class1 第一部分的文档。Class1 第二部分的文档。”

因此，在分部类的多个部分中提供 SDK 文档可能会引发问题。
不过，为了提高代码的可读性和可维护性，仍然建议为类的每个部分编写文档，StyleCop 也要求每个部分都包含文档注释。

使用 `<content>` 标记可以解决此问题，它可以替代分部类中的 `<summary>` 标记。
推荐的做法是在分部类的主要部分提供该类的正式 SDK 文档。
这份文档应使用标准的 `<summary>` 标记。
分部类的所有其他部分都应完全省略 `<summary>` 标记，改用 `<content>` 标记。
这样，开发人员既能为分部类的所有部分编写文档，又能将该类的所有正式 SDK 文档集中在一个部分中。
SDK 文档工具会忽略 `<content>` 标记。

## 如何修复违规

添加 `<summary>` 或 `<content>` 标记，并在其中填写代码元素的说明，即可修复此规则的违规。

以下示例展示了包含已填写内容的 `<summary>` 标记的分部类。

```csharp
/// <summary>
/// Represents a customer in the database.
/// </summary>
public partial class Customer
{
}
```

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.DocumentationRules", "SA1605:PartialElementDocumentationMustHaveSummary", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1605 // PartialElementDocumentationMustHaveSummary
#pragma warning restore SA1605 // PartialElementDocumentationMustHaveSummary
```
