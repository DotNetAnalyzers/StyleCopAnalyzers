# SA1312: 变量名称应以小写字母开头

:memo: 此规则是 StyleCop Analyzers 新增的规则，StyleCop Classic 中没有此规则。

## 原因

C# 变量的名称未以小写字母开头。

## 规则说明

当变量名称未以小写字母开头时，会违反此规则。

如果变量名称需要与 Win32 或 COM 相关项的名称匹配，因此必须以大写字母开头，请将该变量放在特殊的 `NativeMethods` 类中。
`NativeMethods` 类是名称以 `NativeMethods` 结尾的类，用于容纳 Win32 或 COM 包装器。
如果该项位于 `NativeMethods` 类中，StyleCop 会忽略此违规。

对于 `foreach` 迭代变量和 C# 8 `using` 声明，允许使用仅由下划线组成的名称（如 `_` 或 `__`），因为这些位置不能使用弃元。
在其他位置，应使用弃元，而不是名为 `_` 的变量。
例如，应写成 `_ = GetValue();`，而不是 `var _ = GetValue();`。

## 如何修复违规

要修复此规则的违规情况，请将变量名称改为以小写字母开头，或者在合适时将该项放在 `NativeMethods` 类中。

如果名称仅由下划线组成的变量从未被使用，代码修复可以将其替换为弃元（C# 7 及更高版本）。
例如：

| 修复前 | 修复后 |
| --- | --- |
| `var _ = GetValue();` | `_ = GetValue();` |
| `string __ = GetValue();` | `_ = GetValue();` |
| `int.TryParse(text, out var __);` | `int.TryParse(text, out _);` |
| `int.TryParse(text, out int __);` | `int.TryParse(text, out int _);` |
| `var (__, value) = GetPair();` | `var (_, value) = GetPair();` |
| `if (obj is int __)` | `if (obj is int _)` |

在以下情况下，不会提供此代码修复：变量在其他位置被读取或写入；一个声明声明了多个变量，或没有初始值设定项；改为弃元会改变对值应用的转换（例如 `long __ = 1;`、`string __ = null;` 或用户定义的隐式转换）；或者作用域中存在另一个名为 `_` 的符号，导致弃元绑定到该符号。
如果作用域中存在另一个名为 `_` 的符号，`out var __` 会变为 `out var _`，而不是 `out _`。

## 如何抑制违规

```csharp
#pragma warning disable SA1312 // VariableNamesMustBeginWithLowerCaseLetter
int Variable = 3;
#pragma warning restore SA1312 // VariableNamesMustBeginWithLowerCaseLetter
```
