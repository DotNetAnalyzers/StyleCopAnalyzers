# SA1600: 元素应有文档注释

## 原因

C# 代码元素缺少文档注释。

## 规则说明

C# 语法允许使用 XML 文档注释，直接在代码中为类和其他元素编写文档。
有关这些注释及其语法的介绍，请参阅：[https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments](https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments)。

如果元素完全没有文档注释，或者文档注释为空，就会违反此规则。
在 C# 中，以下元素可以有文档注释：类、构造函数、委托、枚举、事件、析构函数、索引器、接口、方法、属性、记录和结构。

### 记录和主构造函数

记录类和记录结构的文档要求与类和结构相同。
记录声明中的位置参数会成为属性；为公共记录编写文档时，除了记录本身的 `<summary>` 文本外，还应为这些参数添加 `<param>` 标记。

对于每个没有匹配的 `<param name="...">` 标记的位置参数，SA1600 都会在参数名称处报告诊断。
参数名称区分大小写。
这些检查遵循文档设置以及记录的有效可访问性，分部记录也不例外。
支持通过 `<include>` 或 `<inheritdoc>` 提供文档。
空的参数文档由 SA1614 检查，而不是 SA1600。

例如：

```csharp
/// <summary>Record.</summary>
/// <param name="Parameter">The value of the generated property.</param>
public record MyRecord(int Parameter);
```

非记录类和结构的主构造函数参数是构造函数参数，而不是属性。
这些声明中缺少参数标记的问题由 [SA1611](SA1611.md) 检查，而不是 SA1600。

### 接口可访问性

`documentInterfaces` 设置为接口声明及其公共成员添加文档要求。默认值 `true`（或 `"all"`）要求内部接口也必须有文档，不受 `documentInternalElements` 的影响。

`"exposed"` 模式仅为可从外部访问的接口及其公共成员添加此要求。此模式使用有效可访问性，并考虑包含类型。`"none"`（或 `false`）模式不添加接口专用的要求，但不会取消常规文档设置的要求。例如，`documentInterfaces: false` 与 `documentExposedElements: true` 一起使用时，仍要求公共接口及其公共成员有文档。

要仅要求可从外部访问的代码有文档，请将 `documentInterfaces` 设置为 `"exposed"`（或 `false`）、`documentExposedElements` 设置为 `true`，并将 `documentInternalElements` 设置为 `false`。`documentPrivateElements` 和 `documentPrivateFields` 保持默认值 `false`。

### 默认接口成员

除非另有指定，否则接口成员隐式为 `public`。
默认接口成员（带有实现的方法、属性、索引器、事件等）遵循以下规则：

* 当配置要求为接口编写文档时（默认如此），公共接口成员仍然需要文档注释。
* 非公共接口成员根据有效可访问性遵循常规文档设置。除非 `documentPrivateElements` 为 `true`，否则私有默认实现不需要文档。私有字段由 `documentPrivateFields` 控制。

类中的显式接口实现不需要单独编写文档；它们从接口定义继承文档。

分部类型、方法、属性、索引器、构造函数和事件改由 [SA1601](SA1601.md) 报告。
对于分部成员，只需为其中一个部分编写文档：如果同一成员的其他部分已有文档，则这两条规则都不会报告未编写文档的部分；只有所有部分都没有文档时，SA1601 才会报告。

## 如何修复违规

为元素添加文档注释，或补全文档注释的内容，即可修复此规则的违规。

以下示例展示了具有有效文档注释的方法：

```csharp
/// <summary>
/// Joins a first name and a last name together into a single string.
/// </summary>
/// <param name="firstName">The first name to join.</param>
/// <param name="lastName">The last name to join.</param>
/// <returns>The joined names.</returns>
public string JoinNames(string firstName, string lastName)
{
    return firstName + " " + lastName;
}
```

下一个示例展示了从基类方法继承文档的方法：

```csharp
/// <summary>
/// Example base class.
/// </summary>
class Vehicle 
{
  /// <summary>
  /// Accelerates the vehicle.
  /// </summary>
  public virtual void Accelerate()
  {                    
    Console.WriteLine("Vehicle is accelerating");
  }
}

/// <summary>
/// Example derived class.
/// </summary>
class Car : Vehicle
{
  /// <inheritdoc/>
  public override void Accelerate()
  {
    Console.Writeline("Car is accelerating");
  }
}
```

从 C# 9 开始，重写方法可以声明协变返回类型。
仍然可以使用 `<inheritdoc/>` 直接从基类成员继承文档：

```csharp
/// <summary>
/// Base factory.
/// </summary>
class WidgetFactory
{
  /// <summary>
  /// Creates a widget.
  /// </summary>
  /// <returns>The newly created <see cref="Widget"/>.</returns>
  public virtual Widget Create() => new Widget();
}

/// <summary>
/// Specialized factory.
/// </summary>
class FancyWidgetFactory : WidgetFactory
{
  /// <inheritdoc/>
  public override FancyWidget Create() => new FancyWidget();
}
```

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.DocumentationRules", "SA1600:ElementsMustBeDocumented", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1600 // ElementsMustBeDocumented
#pragma warning restore SA1600 // ElementsMustBeDocumented
```
