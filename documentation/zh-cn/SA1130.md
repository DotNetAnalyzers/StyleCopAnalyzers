# SA1130: 使用 lambda 语法

:memo: 此规则是 StyleCop Analyzers 新增的规则，StyleCop Classic 中没有此规则。

## 原因

使用 `delegate (parameters) { }` 形式声明了匿名方法，而 lambda 表达式可以通过 `(parameters) => { }` 语法提供等效行为。

## 规则说明

代码中使用“旧式”语法 `delegate (parameters) { }` 定义匿名方法时，会违反此规则。

例如，以下每种写法都会产生违规：

```csharp
Action a = delegate { x = 0; };
Action b = delegate() { y = 0; };
Func<int, int, int> c = delegate(int m, int n) { return m + n; };
Action d = static delegate() { z = 0; };
```

以下代码使用更常见的 lambda 语法展示了等效的变量声明。

```csharp
Action a = () => { x = 0; };
Action b = () => { y = 0; };
Func<int, int, int> c = (m, n) => m + n;
Action d = static () => { z = 0; };
```

:memo: 并非总能将匿名方法替换为等效的 lambda 表达式。
例如，以下代码不会产生任何违规，因为匿名方法和 lambda 表达式的语义不同。

```csharp
var x = A(() => { });       // Expression
var y = A(delegate { });    // Action

private Expression<Action> A(Expression<Action> expression)
{
    return expression;
}

private Action A(Action action)
{
    return action;
}
```

## 如何修复违规

将匿名函数替换为等效的 lambda 表达式即可修复违规。

代码修复会保留匿名方法的参数名称。
lambda 表达式需要参数类型时，也会保留它们：例如 `ref`、`out` 和 `in` 参数，泛型方法通过参数类型推断其类型实参的情况，匿名方法没有转换为委托类型的情况，以及删除类型会导致重载调用不明确的情况。

## 如何抑制违规

```csharp
#pragma warning disable SA1130 // Use lambda syntax
Action a = delegate { x = 0; };
#pragma warning restore SA1130 // Use lambda syntax
```
