# SA1129: 不要使用值类型的默认构造函数

:memo: 此规则是 StyleCop Analyzers 新增的规则，StyleCop Classic 中没有此规则。

## 原因

使用 `new T()` 语法构造了值类型。

## 规则说明

使用 `new T()` 语法构造值类型 `T` 时，会违反此规则。
要创建值类型的默认实例，应改用等效的 `default(T)` 语法。

例如，以下代码会产生违规：

```csharp
ImmutableArray<int> array = new ImmutableArray<int>();
```

上述代码看似创建了一个可以立即使用的新不可变数组，实际上却将 `ImmutableArray<int>` 的默认实例赋给了变量 `array`，几乎任何使用该变量的操作都会导致 `NullReferenceException`。
为避免与引用类型的行为混淆，应始终使用 `default(T)` 语法创建值类型的默认实例。

> :memo: 此建议仅涉及 `default(T)` 与 `new T()` 的区别。
> 其他默认值，包括 `CancellationToken.None`、`0`、`0.0f`、`IntPtr.Zero` 和 `RegexOptions.None`，*不会*产生警告。

## 如何修复违规

将 `new T()` 语法替换为等效的 `default(T)` 语法即可修复违规。

对于通过 `new nint()`/`new nuint()` 构造的本机大小整数，代码修复仅在含义相同的项目中使用 `IntPtr.Zero`/`UIntPtr.Zero`，具体而言，就是使用 C# 11 且运行时支持本机大小整数（例如 .NET 7 或更高版本）的项目。
否则，代码修复会使用 `default(nint)`/`default(nuint)`，以确保与原始代码行为一致。

## 如何抑制违规

```csharp
#pragma warning disable SA1129 // Do not use default value type constructor
IntPtr zero = new IntPtr();
#pragma warning restore SA1129 // Do not use default value type constructor
```
