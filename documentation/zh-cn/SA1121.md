# SA1121: 使用内置类型别名

## 原因

代码使用了某个 C# 基本类型，但没有使用该类型的内置别名。

## 规则说明

代码中任何位置使用了以下类型之一时，会违反此规则：*Boolean、Byte、Char、Decimal、Double、Int16、Int32、Int64、Object、SByte、Single、String、UInt16、UInt32、UInt64*。

使用完整命名空间表示这些类型时，也会违反此规则：*System.Boolean、System.Byte、System.Char、System.Decimal、System.Double、System.Int16、System.Int32、System.Int64、System.Object、System.SByte、System.Single、System.String、System.UInt16、System.UInt32、System.UInt64*。

应始终使用这些类型的内置别名，而不是类型名称或完全限定的类型名称：*bool、byte、char、decimal、double、short、int、long、object、sbyte、float、string、ushort、uint、ulong*。

当 using 别名指向这些类型之一时，诊断会报告在别名目标处，而不是报告在每个别名用法处。
在 C# 12 及更高版本中，可以将目标替换为内置别名；例如，`using MyInt = System.Int32;` 应写为 `using MyInt = int;`。
较早的语言版本不允许在该位置使用内置别名，因此可以在别名声明处抑制此诊断。

下表列出了每个类型的三种表示形式：

| 类型别名 | 类型 | 完全限定的类型 |
| --- | --- | --- |
| bool | Boolean | System.Boolean |
| byte | Byte | System.Byte |
| char | Char | System.Char |
| decimal | Decimal | System.Decimal |
| double | Double | System.Double |
| short | Int16 | System.Int16 |
| int | Int32 | System.Int32 |
| long | Int64 | System.Int64 |
| object | Object | System.Object |
| sbyte | SByte | System.SByte |
| float | Single | System.Single |
| string | String | System.String |
| ushort | UInt16 | System.UInt16 |
| uint | UInt32 | System.UInt32 |
| ulong | UInt64 | System.UInt64 |

### 本机大小的整数（C# 11 和 .NET 7 或更高版本）

本机大小的整数别名 *nint* 和 *nuint* 是在 C# 9 中引入的。
从 C# 11 开始，当目标为 .NET 7 或更高版本时，SA1121 会检查 `IntPtr`/`UIntPtr` 及其别名（通过 `System.Runtime.CompilerServices.RuntimeFeature.NumericIntPtr` 检测）。
在较早的语言版本或运行时中，包括 C# 9，这些类型不会触发 SA1121 诊断。

## 如何修复违规

将类型替换为其内置别名即可修复违规。

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.ReadabilityRules", "SA1121:UseBuiltInTypeAlias", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1121 // UseBuiltInTypeAlias
#pragma warning restore SA1121 // UseBuiltInTypeAlias
```
