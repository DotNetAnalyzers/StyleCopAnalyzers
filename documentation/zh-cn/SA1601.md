# SA1601: 分部元素应有文档注释

## 原因

C# 分部元素缺少文档注释。

## 规则说明

C# 语法允许使用 XML 文档注释，直接在代码中为类和其他元素编写文档。
有关这些注释及其语法的介绍，请参阅：[https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments](https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments)。

如果分部元素（带有 partial 修饰符的元素）完全没有文档注释，或者文档注释为空，就会违反此规则。
在 C# 中，以下元素可以使用 partial 修饰符：类、结构、接口、记录、方法、属性、索引器、构造函数和事件。

对于分部成员（方法、属性、索引器、构造函数和事件），只需为其中一个部分编写文档。
如果实现声明有文档，编译器会使用该文档；否则会使用定义声明的文档。
因此，只有成员的所有部分都没有文档注释时，才会报告分部成员中未编写文档的部分，并且会报告每个这样的部分。
分部类型的处理方式相同：只需为类型的其中一个部分编写文档。

如果在分部类的多个部分中提供文档，这些部分的文档可能会合并为一份文档。
例如，考虑以下分部类的两个部分：

```csharp
/// <summary>
/// Documentation for the first part of Class1.
/// </summary>
public partial class Class1
{
}

/// <summary>
/// Documentation for the second part of Class1.
/// </summary>
public partial class Class1
{
}
```

同一分部类的这两个部分分别为类提供了不同的文档。
将该类的文档生成到 SDK 中时，文档生成工具可能只选择其中一部分而忽略其他部分；在某些情况下，也可能合并两份文档，形成类似这样的文本：“Class1 第一部分的文档。Class1 第二部分的文档。”

因此，在分部类的多个部分中提供 SDK 文档可能会引发问题。
不过，为了提高代码的可读性和可维护性，仍然建议为类的每个部分编写文档，但 StyleCop 只要求其中一个部分包含文档注释。

使用 `<content>` 标记可以解决此问题，它可以替代分部类中的 `<summary>` 标记。
推荐的做法是在分部类的主要部分提供该类的正式 SDK 文档。
这份文档应使用标准的 `<summary>` 标记。
分部类的所有其他部分都应完全省略 `<summary>` 标记，改用 `<content>` 标记。
这样，开发人员既能为分部类的所有部分编写文档，又能将该类的所有正式 SDK 文档集中在一个部分中。
SDK 文档工具会忽略 `<content>` 标记。

## 如何修复违规

为元素添加文档注释，或补全文档注释的内容，即可修复此规则的违规。

以下示例展示了分部类的两个部分，其中一个包含 `<summary>` 文档注释，另一个包含 `<content>` 文档注释。

```csharp
/// <summary>
/// Represents a customer in the database.
/// </summary>
public partial class Customer
{
}

/// <content>
/// Contains auto-generated functionality for the Customer class.
/// </content>
public partial class Customer
{
}
```

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.DocumentationRules", "SA1601:PartialElementsMustBeDocumented", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1601 // PartialElementsMustBeDocumented
#pragma warning restore SA1601 // PartialElementsMustBeDocumented
```
