# SA1143: 条件表达式的格式必须一致

## 原因

条件表达式 (`?:`) 跨越多行，但未使用任何受支持的格式。
此规则默认启用，并在最外层条件表达式的 `?` 标记处报告警告。

## 规则说明

使用以下三种格式之一：

* 将整个表达式放在同一行。
* 将条件放在一行，然后将以 `?` 和 `:` 开头的部分分别放在缩进相同的单独行中。
  每个分支从其运算符所在行开始，并可继续延伸到后续行。运算符所在行的缩进必须大于条件所在行的缩进。
* 对于通过假分支连接的条件链，每行包含一个条件、`?`、真分支和 `:`。
  后续条件和最后的假分支分别从单独的行开始，并与第一个条件对齐。

例如，以下仅部分换行的表达式违反了此规则：

```csharp
var x = condition ? first :
    second;
```

以下格式均有效：

```csharp
var x = condition ? first : second;

var x = condition
    ? first
    : second;

var x = p == "Cat" ? "Animals" :
        p == "Bat" ? "Equipment" :
        p == "Fat" ? "Nutrition" :
        "None";
```

展开格式还允许分支延续到后续行。每个延续行的缩进必须大于其 `?` 或 `:` 运算符的缩进；但以 `{` 或 `}` 开头的行可以与运算符对齐：

```csharp
var x = condition
    ? first * second +
        third * fourth +
        fifth * sixth
    : 0;
```

展开格式也支持带有额外缩进的嵌套假分支：

```csharp
var x = firstCondition
    ? first
    : secondCondition
        ? second
        : third;
```

制表符按配置的制表符宽度解释。此规则不限制行长度。
此规则不添加或删除括号；括号内的表达式也会受到检查。

## 如何修复违规

代码修复提供单行格式和展开的多行格式。对于通过假分支连接的条件链，还提供对齐格式。
每个选项均支持全部修复 (Fix All)。

位于行内且不跨行的块注释会被保留。如果表达式包含行注释、多行注释、指令或无法安全合并到
一行的多行字面量标记，则不提供自动修复。在这些情况下，请手动调整格式，不要更改注释或字面量的内容。

## 如何禁止显示违规

```csharp
#pragma warning disable SA1143 // Conditional expressions must be formatted consistently
// Code containing the violation.
#pragma warning restore SA1143 // Conditional expressions must be formatted consistently
```
