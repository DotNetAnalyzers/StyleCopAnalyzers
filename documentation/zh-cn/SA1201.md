# SA1201: 元素应按正确的顺序排列

## 原因

C# 代码文件中的某个元素相对于其他元素的顺序不正确。

## 规则说明

当文件中的代码元素未遵循标准的排列顺序时，会违反此规则。

要遵循此规则，文件根级别或命名空间中的元素应按以下顺序排列：

* 外部别名指令
* using 指令
* 命名空间
* 委托
* 枚举
* 接口
* 结构
* 类

类、结构或接口内部的元素应按以下顺序排列：

* 字段
* 构造函数
* 终结器（析构函数）
* 委托
* 事件
* 枚举
* 接口
* 扩展块
* 属性
* 索引器
* 转换运算符
* 运算符
* 方法
* 结构
* 类

> 📝 排序时，C# 9 记录按类处理，C# 10 记录结构按结构处理。

> 📝 C# 14 扩展块（`extension(...) { }`）作为独立的元素类型排序，位于接口之后、属性之前。

按元素类型遵循标准的排列顺序，可以提高文件的可读性和可维护性，并促进代码重用。

实现接口时，有时希望将接口的所有成员放在一起。
如果接口包含不同类型的元素，这样做有时会违反此规则。
可以通过分部类解决这一问题。

1. 如果类还不是分部类，为其添加 partial 修饰符。
2. 添加另一个同名的分部类。
   可以将它放在同一个文件中原始类的下方，也可以放在另一个文件中。
3. 将接口继承声明以及接口实现的所有成员移到类的第二个部分。

例如：

```csharp
/// <summary>
/// Represents a customer of the system.
/// </summary>
public partial class Customer
{
    // Contains the main functionality of the class.
}

/// <content>
/// Implements the ICollection class.
/// </content>
public partial class Customer : ICollection
{
    public int Count 
    { 
        get { return this.count; }
    }

    public bool IsSynchronized 
    { 
        get { return false; }
    }

    public object SyncRoot 
    { 
        get { return null; }
    }

    public void CopyTo(Array array, int index)
    {
        throw new NotImplementedException();
    }
}
```

## 如何修复违规

要修复此违规情况，请按上述顺序排列文件中的元素。

即使元素之间存在预处理器指令，仍会报告排序违规。
如果移动会涉及指令，元素排序代码修复不会重新排列成员，因为这可能改变条件编译或其他指令的行为。
请手动重新排列这些元素，同时保留指令边界。

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.OrderingRules", "SA1201:ElementsMustAppearInTheCorrectOrder", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1201 // ElementsMustAppearInTheCorrectOrder
#pragma warning restore SA1201 // ElementsMustAppearInTheCorrectOrder
```
