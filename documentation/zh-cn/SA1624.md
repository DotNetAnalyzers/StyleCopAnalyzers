# SA1624: 属性的摘要文档应省略访问权限受限的访问器

## 原因

C# 属性的 `<summary>` 标记中的文档文本描述了属性的所有访问器，但其中一个访问器的访问权限受限。

## 规则说明

C# 语法允许使用 XML 文档注释，直接在代码中为类和其他元素编写文档。
有关这些注释及其语法的介绍，请参阅：[https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments](https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments)。

如果属性的某个访问器（通常是 set 访问器）的访问权限受限，但属性的摘要文档文本仍然提及两个访问器，就会违反此规则。

通常，属性的摘要文本应以描述属性所公开的访问器类型的措辞开头。
如果属性只有 get 访问器，摘要应以“获取”开头。
如果属性只有 set 访问器，摘要应以“设置”开头。
如果属性同时公开 get 和 set 访问器，摘要文本应以“获取或设置”开头。

但是，当属性中某个访问器的访问级别比属性本身更受限制时，应在摘要文档中省略该访问器。
这也适用于可访问性受限的 `init` 访问器。

有时不容易判断属性的 set 访问器是否真的比 get 访问器更难访问。
例如，公共属性位于 internal 类中，而 set 访问器也被设为 internal。
实际上，get 和 set 访问器具有相同的访问级别。
此时摘要文档应同时提及 get 和 set 访问器，因为它们的有效访问级别相同。

在某些情况下，属性的 set 访问器的访问权限比 get 访问器更受限制。
例如：

```csharp
/// <summary>
/// Gets the name of the customer. 
/// </summary>
public string Name
{
    get { return this.name; }
    private set { this.name = value; }
}
```

在此示例中，set 访问器被设为私有，意味着只有它所在类的成员才能访问它。
而 get 访问器继承所属属性的访问权限；由于属性是公共的，任何调用方都可以访问 get 访问器。

在这种情况下，摘要文档文本应避免提及 set 访问器，因为外部调用方无法访问它。

StyleCop 应用一系列规则，确定属性的摘要文档何时应提及 set 访问器。
通常，只要 set 访问器对与 get 访问器相同的一组调用方可见，或者对外部类或派生类可见，就应在摘要中提及它。

确定是否应在属性的摘要文档中包含 set 访问器的具体规则如下：

1. set 访问器与 get 访问器具有相同的访问级别。
   例如：

    ```csharp
    /// <summary>
    /// Gets or sets the name of the customer. 
    /// </summary>
    protected string Name
    {
        get { return this.name; }
        set { this.name = value; }
    }
    ```

2. 属性只能在程序集内部访问，并且 set 访问器也具有 internal 访问权限。
   例如：

    ```csharp
    internal class Class1
    {
        /// <summary>
        /// Gets or sets the name of the customer. 
        /// </summary>
        protected string Name
        {
            get { return this.name; }
            internal set { this.name = value; }
        }
    }

    internal class Class1
    {
        public class Class2
        {
            /// <summary>
            /// Gets or sets the name of the customer. 
            /// </summary>
            public string Name
            {
                get { return this.name; }
                internal set { this.name = value; }
            }
        }
    }
    ```

3. 属性是私有的，或者嵌套在私有类之内，且 set 访问器的访问修饰符不是 private。
   在下面的示例中，set 访问器上声明的访问修饰符没有实际意义，因为 set 访问器位于私有类中，Class1 以外的其他类无法访问它。
   因此，set 访问器实际上与 get 访问器具有相同的访问级别。

    ```csharp
    public class Class1
    {
        private class Class2
        {
            public class Class3
            {
                /// <summary>
                /// Gets or sets the name of the customer. 
                /// </summary>
                public string Name
                {
                    get { return this.name; }
                    internal set { this.name = value; }
                }
            }
        }
    }
    ```

4. 只要 set 访问器具有 protected 或 protected internal 访问权限，就应在文档中提及它。
   从属性所在类派生的类始终可以访问 protected 或 protected internal 的 set 访问器。

    ```csharp
    internal class Class1
    {
        public class Class2
        {
            /// <summary>
            /// Gets or sets the name of the customer. 
            /// </summary>
            internal string Name
            {
                get { return this.name; }
                protected set { this.name = value; }
            }
        }

        private class Class3 : Class2
        {
            public Class3(string name) { this.Name = name; }
        }
    }
    ```

## 如何修复违规

更新属性的摘要文本，删除提及访问权限受限的访问器的措辞，即可修复此规则的违规。

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.DocumentationRules", "SA1624:PropertySummaryDocumentationMustOmitSetAccessorWithRestrictedAccess", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1624 // PropertySummaryDocumentationMustOmitSetAccessorWithRestrictedAccess
#pragma warning restore SA1624 // PropertySummaryDocumentationMustOmitSetAccessorWithRestrictedAccess
```
