# SA1202: 元素应按访问级别排序

## 原因

C# 代码文件中的某个元素相对于其他元素，未按访问级别正确排列。

## 规则说明

当文件中的代码元素未遵循基于访问级别的标准排列顺序时，会违反此规则。

要遵循此规则，相邻且同类型的元素应按以下访问级别顺序排列：

* public
* internal
* protected internal
* protected
* private protected
* private

:memo: 对于此规则，静态构造函数以及显式实现的接口方法、属性、索引器和事件均视为 *public*。
StyleCop Classic 将显式接口事件视为私有成员；此处将其视为公共成员是有意的，与其他显式接口成员保持一致。

按访问级别遵循标准的排列顺序，可以提高文件的可读性和可维护性，并使类对外公开的接口更容易识别。

### 接口和默认接口成员

默认接口成员（包括带实现的成员和静态接口成员）遵循与类成员相同的访问级别排序规则。
在接口内部，`public` 成员应位于 `internal`、`protected internal`、`protected`、`private protected` 和 `private` 成员之前。

### 记录和主构造函数

记录（包括位置记录）和记录结构遵循与类和结构相同的排序规则。
成为属性的主构造函数参数不会改变其余成员应遵循的访问级别顺序。

### 存在依赖关系的字段

如果字段的初始值设定项引用了包含类型中的其他非常量字段，就必须按文本声明顺序进行初始化。
如果访问级别较高的字段直接或间接依赖于前面的字段，或依赖于另一个必须位于前面字段之后的字段，则允许它位于访问级别较低的字段之后。

## 如何修复违规

要修复此违规情况，请按上述顺序排列文件中的元素。

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.OrderingRules", "SA1202:ElementsMustBeOrderedByAccess", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1202 // ElementsMustBeOrderedByAccess
#pragma warning restore SA1202 // ElementsMustBeOrderedByAccess
```
