# SA1649: 文件名应与第一个类型的名称匹配

## 原因

C# 代码文件的文件名与文件中声明的第一个类型的名称不匹配。
对于定义为 `Class1<T>` 的泛型类型，根据 `fileNamingConvention` 设置，文件名应为 `Class1{T}.cs` 或 ``Class1`1.cs``。
有关详细信息，请参阅 [Configuration.md](Configuration.md)。

分部类会被忽略。

包含顶级语句的文件不受此规则约束。即使文件还声明了辅助类型，顶级程序文件通常也命名为 `Program.cs`。

## 规则说明

如果 C# 文件的文件名没有包含文件中第一个类型的名称，就会违反此规则。
例如，名为 Class1.cs 的 C# 源文件包含以下代码：

```csharp
public class Class2
{
}
```

由于文件名没有包含文件中第一个类型的正确名称，此文件会违反此规则。
文件应写成：

```csharp
public class Class1
{
}
```

类型上的 `readonly` 修饰符（例如 `readonly struct`），或第一个类型内部成员上的 `readonly` 修饰符（例如 C# 8 的只读结构成员），不会改变预期的文件名。
分析器仍然使用第一个非分部类型的标识符，因此声明为 `public readonly struct Point` 的类型仍应放在 `Point.cs` 中。

确定文件名时，会解析标识符中的 Unicode 转义序列。
例如，`class Name\u0065 { }` 应放在 `Namee.cs` 中，而不是名称中包含转义序列的文件中。
同样，逐字标识符的 `@` 前缀也不是预期文件名的一部分。

## 如何修复违规

重命名文件，使其名称与文件中第一个类型的名称匹配，即可修复此规则的违规。

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.DocumentationRules", "SA1649:FileNameMustMatchTypeName", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1649 // SA1649FileNameMustMatchTypeName
#pragma warning restore SA1649 // SA1649FileNameMustMatchTypeName
```
