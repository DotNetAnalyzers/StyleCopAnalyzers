# SA1200: using 指令应放置在正确的位置

## 原因

C# using 指令位于命名空间元素外部。

> :memo: 此规则的行为可能随 **stylecop.json** 中 `usingDirectivesPlacement` 属性的配置而变化。
> 有关详细信息，请参阅 [Configuration.md](Configuration.md#using-directives)。

## 规则说明

当 using 指令或 using 别名指令位于命名空间元素外部时，会违反此规则；但文件不包含任何命名空间元素时除外。

> :memo: 对于 C# 9 顶级语句，所有 `using` 指令都必须位于任何可执行代码之前。
> 如果文件包含顶级语句（因此没有命名空间声明），无论 `usingDirectivesPlacement` 的配置值如何，文件顶部的 using 指令都视为正确。

> :memo: 全局 using 指令（C# 10）始终位于命名空间外部；如果放在命名空间内部，编译器会报错。
> SA1200 不会针对全局 using 指令的位置报告诊断。

例如，以下代码会产生两处违反此规则的情况。

```csharp
using System;
using Guid = System.Guid;

namespace Microsoft.Sample
{
    public class Program
    {
    }
}
```

不过，以下代码不会违反此规则：

```csharp
namespace Microsoft.Sample
{
    using System;
    using Guid = System.Guid;
 
    public class Program
    {
    }
}
```

将 using 指令放在命名空间元素内部而非外部，会产生一些细微的差异，包括：

1. 将 using 别名指令放在命名空间内部，可以避免编译器在存在冲突的类型之间产生混淆。
2. 当一个文件定义了多个命名空间时，将 using 指令放在命名空间元素内部，可以限定引用和别名的作用域。

### 1. 避免类型混淆

考虑以下代码，其中的 using 别名指令定义在命名空间元素外部。
代码创建了一个名为 *Guid* 的新类，同时定义了一条 using 别名指令，将名称 *Guid* 映射到类型 *System.Guid*。
最后，代码创建了 *Guid* 类型的实例：

```csharp
using Guid = System.Guid;
 
namespace Microsoft.Sample
{
    public class Guid
    {
        public Guid(string s)
        {
        }
    }

    public class Program
    {
        public static void Main(string[] args)
        {
            Guid g = new Guid("hello");
        }
    }
}
```

这段代码能够成功编译，不产生任何编译错误。
但是，究竟实例化了哪一个 *Guid* 类型并不直观。
如果像下面这样将 using 指令移到命名空间内部，就会发生编译错误：

```csharp
namespace Microsoft.Sample
{
    using Guid = System.Guid;

    public class Guid
    {
        public Guid(string s)
        {
        }
    }

    public class Program
    {
        public static void Main(string[] args)
        {
            Guid g = new Guid("hello");
        }
    }
}
```

包含 `Guid g = new Guid("hello");` 的那一行会产生以下编译错误：

> CS0576：命名空间“Microsoft.Sample”包含与别名“Guid”冲突的定义

这段代码为 *System.Guid* 类型创建了名为 *Guid* 的别名，还创建了自己的 *Guid* 类型，并为其提供了匹配的构造函数接口。
随后，代码创建了 *Guid* 类型的实例。
为了创建此实例，编译器必须在两个不同的 *Guid* 定义之间做出选择。
当 using 别名指令位于命名空间元素外部时，编译器会选择在当前命名空间内部定义的本地 *Guid* 类型，而完全忽略命名空间外部定义的 using 别名指令。
遗憾的是，仅从阅读代码很难看出这一点。

但是，当 using 别名指令位于命名空间内部时，编译器必须在同一命名空间中定义的两个相互冲突的 *Guid* 类型之间做出选择。
这两个类型都提供了匹配的构造函数。
编译器无法做出决定，因此报告编译错误。

将 using 别名指令放在命名空间外部不是良好的做法，因为在上述情形中，实际使用的是哪一个类型并不明确，容易造成混淆。
这可能导致难以诊断的错误。

将 using 别名指令放在命名空间元素内部，可以消除这一错误来源。

### 2. 多个命名空间

一般不建议在一个文件中放置多个命名空间元素。
但如果确实这样做了，最好将所有 using 指令分别放在各自的命名空间元素内部，而不是统一放在文件顶部。
这样可以严格限定命名空间的作用域，也有助于避免上述行为。

需要特别注意：如果已有代码将 using 指令放在命名空间外部，在将这些指令移到命名空间内部时，应确保不会改变代码的语义。
如上所述，将 using 别名指令放在命名空间元素内部，会使编译器以不同于指令位于外部时的方式处理冲突的类型。

### 文件范围命名空间（C# 10）

文件范围命名空间声明不包含出现在它之前的 using 指令。
`namespace Microsoft.Sample;` 之前的普通 using 指令和 using 别名指令位于命名空间外部；之后的则位于命名空间内部。
在默认的 `usingDirectivesPlacement` 值 `insideNamespace` 下，以下代码会产生两处 SA1200 违规：

```csharp
using System;
using Guid = System.Guid;

namespace Microsoft.Sample;

public class Program
{
}
```

要符合默认配置，请将这些指令放在文件范围命名空间声明之后：

```csharp
global using System.Collections.Generic;

namespace Microsoft.Sample;

using System;
using Guid = System.Guid;

public class Program
{
}
```

全局 using 指令必须放在命名空间声明之前（如上例所示）；SA1200 不检查其位置。
如果将 `usingDirectivesPlacement` 配置为 `outsideNamespace`，则普通 using 指令和 using 别名指令必须放在文件范围命名空间声明之前，如第一个示例所示。
配置为 `preserve` 时，SA1200 允许这两种位置。
有关配置详情，请参阅[using 指令的位置](Configuration.md#using-directives-placement)。

## 如何修复违规

要修复此规则的违规情况，请将所有 using 指令和 using 别名指令移到命名空间元素内部。

## 如何抑制违规

```csharp
[SuppressMessage("StyleCop.CSharp.OrderingRules", "SA1200:UsingDirectivesMustBePlacedWithinNamespace", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1200 // UsingDirectivesMustBePlacedWithinNamespace
#pragma warning restore SA1200 // UsingDirectivesMustBePlacedWithinNamespace
```
