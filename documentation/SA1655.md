# SA1655: Documentation element tags must be consistently placed

## Cause

The opening tag of an XML documentation element is on a line by itself, but the closing tag is not (or the other way around).

## Rule description

For every element in an XML documentation comment, either both the opening and closing tags are on lines by
themselves (preceded only by the `///` comment prefix, and followed by nothing), or neither is.

The following are allowed:

```csharp
/// <summary>Summary text.</summary>
///
/// <summary>
/// Summary text.
/// </summary>
///
/// <remarks>Text that spans
/// multiple lines.</remarks>
```

The tags of an element *may* appear on different lines without being on lines by themselves, for example:

```csharp
/// <para>Paragraph text
/// more text.</para>
```

The following violate the rule:

```csharp
/// <summary>
/// Summary text.</summary>
///
/// <summary>Summary text
/// </summary>
///
/// <para>
/// Paragraph text.</para>
```

This rule applies to every element, including `<para>`, and to elements nested inside other elements.

## How to fix violations

Either move both tags onto lines by themselves, or keep the text on the same lines as both tags:

```csharp
/// <summary>
/// Summary text.
/// </summary>
```

## How to suppress violations

```csharp
[SuppressMessage("StyleCop.CSharp.DocumentationRules", "SA1655:DocumentationElementTagsMustBeConsistentlyPlaced", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1655 // Documentation element tags must be consistently placed
#pragma warning restore SA1655 // Documentation element tags must be consistently placed
```
