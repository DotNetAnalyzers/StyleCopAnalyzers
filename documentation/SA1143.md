# SA1143: Conditional expressions must be formatted consistently

## Cause

A conditional (`?:`) expression spans multiple lines without using one of the supported layouts.
This rule is enabled by default and reports a warning at the outermost conditional's `?` token.

## Rule description

Use one of these three layouts:

* The entire expression on one line.
* The condition, which may span multiple lines, followed by separate, equally indented lines beginning
  with `?` and `:`. Each branch starts on its operator's line and may continue on additional lines. The
  operator lines must be indented beyond the indentation of the condition's last line.
* For a chain through the false branches, one condition, `?`, true branch, and `:` per line.
  Subsequent conditions and the final false branch start on separate lines aligned with the first condition.

For example, the following partially wrapped expression violates the rule:

```csharp
var x = condition ? first :
    second;
```

Each of these layouts is valid:

```csharp
var x = condition ? first : second;

var x = condition
    ? first
    : second;

var x = p == "Cat" ? "Animals" :
        p == "Bat" ? "Equipment" :
        p == "Fat" ? "Nutrition" :
        "None";
```

The expanded layout also allows a branch to continue over additional lines. Each continuation line must be
indented beyond its `?` or `:` operator, except that a line starting with `{` or `}` may align with the operator:

```csharp
var x = condition &&
        otherCondition
            ? first * second +
                third * fourth +
                fifth * sixth
            : 0;
```

The expanded layout also supports nested false branches, with additional indentation:

```csharp
var x = firstCondition
    ? first
    : secondCondition
        ? second
        : third;
```

Tabs are interpreted using the configured tab width. This rule does not impose a line-length limit.
The rule does not add or remove parentheses; parenthesized expressions are not exempt.

## How to fix violations

The code fix offers a single-line layout and an expanded multiline layout. For false-branch chains it
also offers the aligned-chain layout. Each choice supports Fix All.

These layout choices preserve inline, single-line block comments. They are not offered if the expression contains
line comments, multiline comments, directives, or multiline literal tokens that cannot safely be flattened.

A separate code fix aligns underindented closing delimiters with their matching opening delimiters in
multiline branches. It supports collection expressions, object and collection initializers, tuples, and
parenthesized expressions. For example:

```csharp
static string[] Foo(bool condition) =>
    condition
        ? [
            "a",
            "b",
          ]
        : [];
```

This action changes only the closing delimiters' leading whitespace. It preserves line breaks, comments,
blank lines, literal contents, and unrelated expression formatting, using the configured tab width and
indentation style. It supports Fix All and is offered only when the correction resolves SA1143 throughout
the conditional expression without changing directives. If no safe correction is available, adjust the
layout manually without changing the contents of comments or literals.

## How to suppress violations

```csharp
#pragma warning disable SA1143 // Conditional expressions must be formatted consistently
// Code containing the violation.
#pragma warning restore SA1143 // Conditional expressions must be formatted consistently
```
