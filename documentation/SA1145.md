# SA1145: Do not use assignment as condition

## Cause

An assignment expression is used as a condition, or as an operand of a logical operator.
This rule is enabled by default and reports a warning at the assignment expression.

## Rule description

Using `=` instead of `==` in a condition usually fails to compile in C#, but it compiles when the assigned
value is a `bool`. This rule reports an assignment (simple, compound, or `??=`) when, after skipping any
parentheses, its parent is one of the following:

* The conditional AND (`&&`), conditional OR (`||`), or logical NOT (`!`) operator
* The condition of a conditional (`?:`) expression
* The condition of an `if`, `while`, `do`...`while`, or `for` statement
* An exception filter (`when` clause)

The following code violates the rule:

```csharp
bool flag = false;
if (flag = Compute())
{
}

while (!(done = Step()))
{
}
```

Assignments that are compared with another value are not reported:

```csharp
string line;
while ((line = reader.ReadLine()) != null)
{
}
```

## How to fix violations

Replace the assignment with a comparison, or move the assignment into its own statement.

```csharp
bool flag = Compute();
if (flag)
{
}
```

## How to suppress violations

```csharp
#pragma warning disable SA1145 // Do not use assignment as condition
// Code containing the violation.
#pragma warning restore SA1145 // Do not use assignment as condition
```
