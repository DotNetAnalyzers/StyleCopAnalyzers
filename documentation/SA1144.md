# SA1144: Zero-width characters in literals must be escaped

## Cause

A string or character literal contains a zero-width character written directly in the source text.

## Rule description

Zero-width characters are invisible in most editors, so they are easy to introduce by accident (for example, by pasting text from a web page) and hard to find later. This rule reports string, character, UTF-8 string and interpolated string literals that contain any of these characters:

* U+200B ZERO WIDTH SPACE
* U+2060 WORD JOINER
* U+FEFF ZERO WIDTH NO-BREAK SPACE

One diagnostic is reported for each literal token. Zero-width joiners and non-joiners (U+200D and U+200C) are not reported because they are meaningful in some scripts and in emoji sequences.

```csharp
string value = "a​b"; // contains an invisible U+200B between 'a' and 'b'
```

## How to fix violations

Replace each zero-width character with its escape sequence. The code fix does this for regular string, character and (non-verbatim) interpolated string literals:

```csharp
string value = "a\u200Bb";
```

A second code fix removes the zero-width characters instead, for string literals of every kind. It is not offered for character literals. Verbatim strings and raw string literals do not support escape sequences, so for those literals only the removal fix is offered; to keep the character, build the string with an escape sequence, for example by concatenating `"\u200B"`.

## How to suppress violations

```csharp
#pragma warning disable SA1144 // Zero-width characters in literals must be escaped
// Code containing the violation.
#pragma warning restore SA1144 // Zero-width characters in literals must be escaped
```
