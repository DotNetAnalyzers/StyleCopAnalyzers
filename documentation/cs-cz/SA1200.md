# SA1200: Using directives should be placed correctly

## Příčina

Direktiva `using` jazyka C# je umístěna mimo prvek oboru názvů.

> :memo: Chování tohoto pravidla se může změnit podle konfigurace vlastnosti `usingDirectivesPlacement` v souboru **stylecop.json**. Další informace najdete v souboru [Configuration.md](Configuration.md#using-directives).

## Popis pravidla

K porušení tohoto pravidla dochází, když je direktiva `using` nebo direktiva aliasu `using` umístěna mimo prvek oboru názvů, pokud soubor neobsahuje žádné prvky oboru názvů.

> :memo: U příkazů nejvyšší úrovně v C# 9 se všechny direktivy `using` musí nacházet před veškerým spustitelným kódem. Pokud soubor obsahuje příkazy nejvyšší úrovně (a tedy neobsahuje deklaraci oboru názvů), jsou direktivy `using` na začátku souboru považovány za správné bez ohledu na hodnotu konfigurace `usingDirectivesPlacement`.

> :memo: Globální direktivy `using` (C# 10) jsou vždy mimo obory názvů a kompilátor při jejich umístění dovnitř vyvolá chybu. SA1200 nehlásí diagnostiku pro umístění globálních direktiv `using`.

Například následující kód by vedl ke dvěma porušením tohoto pravidla.

```csharp
using System;
using Guid = System.Guid;

namespace Microsoft.Sample
{
    public class Program
    {
    }
}
```

Následující kód by naopak k žádnému porušení tohoto pravidla nevedl:

```csharp
namespace Microsoft.Sample
{
    using System;
    using Guid = System.Guid;
 
    public class Program
    {
    }
}
```

Umístění direktiv `using` do prvku oboru názvů namísto mimo obor názvů má mimo jiné následující jemné rozdíly:

1. Umístění direktiv aliasu `using` do oboru názvů odstraňuje nejednoznačnost kompilátoru mezi konfliktními typy.

2. Pokud je v jednom souboru definováno více oborů názvů, umístění direktiv `using` do jejich prvků vymezuje rozsah odkazů a aliasů.

### 1. Odstranění nejednoznačnosti typů

Zvažte následující kód, který obsahuje direktivu aliasu `using` definovanou mimo prvek oboru názvů. Kód vytvoří novou třídu nazvanou *Guid* a také definuje direktivu aliasu `using`, která mapuje název *Guid* na typ *System.Guid*. Nakonec kód vytvoří instanci typu *Guid*:

```csharp
using Guid = System.Guid;
 
namespace Microsoft.Sample
{
    public class Guid
    {
        public Guid(string s)
        {
        }
    }

    public class Program
    {
        public static void Main(string[] args)
        {
            Guid g = new Guid("hello");
        }
    }
}
```

Tento kód se zkompiluje bez chyb kompilátoru. Není však jasné, která verze typu *Guid* je vytvářena. Pokud se direktiva `using` přesune dovnitř oboru názvů, jak je ukázáno níže, dojde k chybě kompilátoru:

```csharp
namespace Microsoft.Sample
{
    using Guid = System.Guid;

    public class Guid
    {
        public Guid(string s)
        {
        }
    }

    public class Program
    {
        public static void Main(string[] args)
        {
            Guid g = new Guid("hello");
        }
    }
}
```

Kód selže s následující chybou kompilátoru na řádku obsahujícím `Guid g = new Guid("hello");`

> CS0576: Namespace 'Microsoft.Sample' contains a definition conflicting with alias 'Guid'

Kód vytvoří alias pro typ *System.Guid* nazvaný *Guid* a vlastní typ *Guid* s odpovídajícím konstruktorem. Později vytvoří instanci typu *Guid*. Kompilátor musí zvolit mezi dvěma definicemi *Guid*. Je-li direktiva aliasu `using` mimo prvek oboru názvů, zvolí místní definici *Guid* a direktivu aliasu `using` mimo obor názvů ignoruje. To při čtení kódu není zřejmé.

Je-li direktiva aliasu `using` v oboru názvů, musí kompilátor volit mezi dvěma konfliktními typy *Guid* definovanými ve stejném oboru názvů. Oba poskytují odpovídající konstruktor. Kompilátor se nedokáže rozhodnout a oznámí chybu.

Umístění direktivy aliasu `using` mimo obor názvů je špatný postup, protože v podobných situacích není zřejmé, která verze typu se používá. To může vést k obtížně diagnostikovatelné chybě.

Umístění direktiv aliasu `using` do prvku oboru názvů tento zdroj chyb eliminuje.

### 2. Více oborů názvů

Umístění více prvků oborů názvů do jednoho souboru je obecně špatný nápad, ale pokud se tak stane, je vhodné umístit všechny direktivy `using` do jednotlivých prvků oborů názvů místo globálně na začátek souboru. Tím se rozsah oborů názvů přesně vymezí a také se předejde výše popsanému chování.

Je důležité poznamenat, že při přesunu direktiv `using` z vnějšku oboru názvů dovnitř je nutné ověřit, že se nezmění sémantika kódu. Jak bylo vysvětleno výše, direktivy aliasu `using` v prvku oboru názvů umožňují kompilátoru volit mezi konfliktními typy způsoby, které při umístění direktiv mimo obor názvů nenastanou.

## Jak opravit porušení

Chcete-li porušení tohoto pravidla opravit, přesuňte všechny direktivy `using` a direktivy aliasu `using` do prvku oboru názvů.

## Jak potlačit porušení

```csharp
[SuppressMessage("StyleCop.CSharp.OrderingRules", "SA1200:UsingDirectivesMustBePlacedWithinNamespace", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1200 // UsingDirectivesMustBePlacedWithinNamespace
#pragma warning restore SA1200 // UsingDirectivesMustBePlacedWithinNamespace
```
