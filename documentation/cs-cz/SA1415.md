# SA1415: Do not use public on members of internal types

:bulb: This rule is disabled by default.

## Cause

A member of a type that is effectively internal or private is declared `public`.

## Rule description

A violation of this rule occurs when a member is declared `public` but its containing type is not visible outside the assembly. A `public` member of an `internal` or `private` type is not part of the assembly's public API; it is only as visible as the type itself. Reviewers who watch for new public API often have to look past these members.

This rule reports an explicit `public` modifier on a member of a type whose effective accessibility is `internal`, `private`, or `private protected`. That includes members of:

* top-level `internal` types
* `private` or `internal` nested types
* `public` or `protected` types nested in an `internal` type, which are themselves effectively internal
* `private protected` nested types (including those nested in a public type), which are not visible outside the assembly
* `file` types

The following are not reported:

* Members of types that are effectively `public`, `protected`, or `protected internal` (these can be visible outside the assembly)
* Members that implement an interface or override a base member, which must remain `public`
* User-defined operators and conversions, which the language requires to be `public`
* Members of interfaces (including internal interfaces) and enum members
* Members that are not declared `public`, including implicit public positional properties of records such as `internal record R(int Value)`
* `protected` or `protected internal` members of internal types

This rule is disabled by default because not every team wants to treat `public` on internal types as a problem. Some teams use `public` on internal types to mark members they intend to promote later.

To enable the rule, add this to an `.editorconfig` file:

```ini
dotnet_diagnostic.SA1415.severity = warning
```

## How to fix violations

Change the member's accessibility from `public` to `internal`. The two are equivalent for members of types that are not visible outside the assembly, and `internal` does not appear to be part of the public API.

```csharp
internal class Example
{
    public void Method() // SA1415
    {
    }
}
```

```csharp
internal class Example
{
    internal void Method()
    {
    }
}
```

## How to suppress violations

```csharp
[SuppressMessage("StyleCop.CSharp.MaintainabilityRules", "SA1415:DoNotUsePublicOnMembersOfInternalTypes", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1415 // Do not use public on members of internal types
#pragma warning restore SA1415 // Do not use public on members of internal types
```
