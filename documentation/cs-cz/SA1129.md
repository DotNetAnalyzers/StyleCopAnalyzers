# SA1129: Do not use default value type constructor

:memo: Toto pravidlo je nové pro StyleCop Analyzers a v StyleCop Classic neexistovalo.

## Příčina

Hodnotový typ byl vytvořen pomocí syntaxe `new T()`.

## Popis pravidla

K porušení tohoto pravidla dochází, když je hodnotový typ `T` vytvořen pomocí syntaxe `new T()`. Chcete-li vytvořit výchozí instanci hodnotového typu, použijte místo toho ekvivalentní syntaxi `default(T)`.

Následující kód například porušuje toto pravidlo:

```csharp
ImmutableArray<int> array = new ImmutableArray<int>();
```

Přestože se může zdát, že se výše uvedeným kódem vytvoří nové neměnitelné pole připravené k použití, proměnné `array` se ve skutečnosti přiřadí výchozí instance typu `ImmutableArray<int>` a téměř každý pokus o použití této proměnné skončí výjimkou `NullReferenceException`. Aby nedocházelo k záměně s chováním referenčních typů, mají se výchozí instance hodnotových typů vždy vytvářet pomocí syntaxe `default(T)`.

> :memo: Toto pravidlo se týká pouze rozdílu mezi zápisy `default(T)` a `new T()`. Jiné výchozí hodnoty, například
> `CancellationToken.None`, `0`, `0.0f`, `IntPtr.Zero` a `RegexOptions.None`, varování *nevyvolají*.

## Jak opravit porušení

Chcete-li opravit porušení tohoto pravidla, nahraďte syntaxi `new T()` ekvivalentní syntaxí `default(T)`.

U celých čísel nativní velikosti vytvořených pomocí `new nint()`/`new nuint()` použije oprava kódu `IntPtr.Zero`/`UIntPtr.Zero` pouze v projektech, kde mají tyto zápisy stejný význam, konkrétně v C# 11 s podporou celých čísel nativní velikosti v modulu runtime (například .NET 7 nebo novějším). Jinak oprava kódu použije `default(nint)`/`default(nuint)`, aby zachovala stejné chování jako původní kód.

## Jak potlačit porušení

```csharp
#pragma warning disable SA1129 // Do not use default value type constructor
IntPtr zero = new IntPtr();
#pragma warning restore SA1129 // Do not use default value type constructor
```
