# SA1137: Elements should have the same indentation

:memo: Toto pravidlo je nové pro StyleCop Analyzers a v StyleCop Classic neexistovalo.

## Příčina

Dva sourozenecké prvky, které každý začínají na vlastním řádku, mají různou úroveň odsazení.

## Popis pravidla

K porušení tohoto pravidla dochází, když dva nebo více sourozeneckých prvků začínají každý na vlastním řádku, ale nejsou odsazeny stejně.

Následující kód například porušuje toto pravidlo:

```csharp
public void MethodName()
{
    A();
   B(); // SA1137: Očekává se odsazení shodné s předchozím řádkem
}
```

Následující kód žádné porušení nezpůsobí:

```csharp
public void MethodName()
{
    A();
    B();
}
```

Toto pravidlo nekontroluje relativní odsazení ani odsazení v nezávislých skupinách sourozeneckých prvků. Následující
kód ukazuje složitější příklad, který žádné porušení nezpůsobí:

```csharp
public void Method1()
{
    A();
    B();
}

public void Method2()
{
        A();
        B();
}

public void Method3()
{
A();
B();
}

public void Method4()
    {
    A();
    B();
    }
```

### Atributy

Seznamy atributů toto pravidlo vyhodnocuje jako samostatné prvky na stejné úrovni jako prvek, na který se vztahují.
Při určování očekávaného odsazení sourozeneckých prvků však mají seznamy atributů nižší prioritu. Jinými slovy,
očekávané odsazení skupiny určuje první prvek ve stejné skupině, který začíná na vlastním řádku, pokud takový prvek
existuje. Pokud neexistuje, použije se místo toho odsazení prvního seznamu atributů. Následující kód ukazuje, kde se
vzhledem k seznamům atributů hlásí diagnostika SA1137.

```csharp
  [Obsolete]                // SA1137 (očekává se nulové odsazení)
public void Method()        // V pořádku (tento řádek určuje odsazení skupiny)
{
}

  public Task MethodAsync() // SA1137 (očekává se nulové odsazení)
    {                       // V pořádku (není součástí skupiny analyzované pravidlem)
    }
```

Následující příklad ukazuje případ, kdy se pro skupinu *použije* odsazení seznamu atributů.

```csharp
public void Method(int x,   // Ignorováno (parametr nezačíná na vlastním řádku)
    [In] int y,             // V pořádku (tento řádek určuje odsazení skupiny)
      [In] int z)           // SA1137
{
}
```

### Popisky

Popisky uvnitř bloku příkazů se vyhodnocují zvláštním způsobem. Očekává se, že všechny popisky v bloku budou mít stejné
odsazení, i když se liší od odsazení příkazů v bloku. Toto pravidlo nekontroluje konkrétní odsazení popisků vzhledem k
ostatním příkazům.

Následující příklad ukazuje blok s příkazy a popisky.

```csharp
public int MethodName()
{
    int x;

  beginning:    // V pořádku (odsazení popisku se může lišit od ostatních příkazů)
     x = 3;     // SA1137 (má být odsazeno čtyřmi mezerami jako výše uvedený řádek 'int x;')

end:            // SA1137 (má být odsazeno dvěma mezerami jako výše uvedený popisek 'beginning:')
    return x;
}
```

Uvnitř příkazu `switch` tvoří popisky `case` a `default` další kategorii. V tomto případě platí tato pravidla:

1. Popisky `case` a `default` v příkazu `switch` musí mít stejné odsazení.
2. Ostatní popisky v příkazu `switch` musí mít stejné odsazení, které se však může lišit od odsazení popisků `case`.
3. Příkazy v příkazu `switch` musí mít stejné odsazení, které se však může lišit od odsazení obou výše uvedených typů popisků.

## Jak opravit porušení

Chcete-li opravit porušení tohoto pravidla, upravte odsazení sourozeneckých prvků tak, aby se shodovalo.

Pokud nesprávně zarovnané závorky inicializátoru pole začínají každá na vlastním řádku a otevírací závorka nemá
odsazení, ale obsahující výraz je odsazený, oprava kódu zarovná obě závorky s výrazem a odsadí prvky o jednu
úroveň hlouběji, přičemž zachová komentáře.
Toto chování opravy kódu nemění, která porušení pravidlo hlásí.

## Jak potlačit porušení

```csharp
class TypeName { }

#pragma warning disable SA1137 // Elements should have the same indentation
  class Indented { }
#pragma warning restore SA1137 // Elements should have the same indentation
```
