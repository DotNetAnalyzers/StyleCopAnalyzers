# SA1600: Elements should be documented

## Příčina

Prvek kódu C# postrádá záhlaví dokumentace.

## Popis pravidla

Syntaxe C# poskytuje mechanismus pro vkládání dokumentace tříd a prvků přímo do kódu pomocí záhlaví dokumentace XML. Úvod k těmto záhlavím a popis jejich syntaxe najdete v následujícím článku: [https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments](https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments).

Porušení tohoto pravidla nastává, pokud prvek zcela postrádá záhlaví dokumentace nebo je záhlaví prázdné. V C# mohou záhlaví dokumentace mít následující typy prvků: třídy, konstruktory, delegáty, výčty, události, finalizátory, indexery, rozhraní, metody, vlastnosti, záznamy a struktury.

### Záznamy a primární konstruktory

Třídy záznamů a struktury záznamů se řídí stejnými požadavky jako třídy a struktury. Poziční parametry v deklaraci záznamu se stanou vlastnostmi; při dokumentování veřejného záznamu zahrňte pro tyto parametry značky `<param>` kromě textu `<summary>` pro samotný záznam.

SA1600 hlásí každý poziční parametr bez odpovídající značky `<param name="...">` u názvu parametru. V názvech parametrů se rozlišují malá a velká písmena. Tyto kontroly se řídí nastavením dokumentace a efektivní přístupností záznamu, včetně částečných záznamů. Podporována je dokumentace poskytnutá prostřednictvím `<include>` nebo `<inheritdoc>`. Prázdnou dokumentaci parametrů kontroluje SA1614, nikoli SA1600.

Například:

```csharp
/// <summary>Record.</summary>
/// <param name="Parameter">The value of the generated property.</param>
public record MyRecord(int Parameter);
```

Parametry primárního konstruktoru tříd a struktur, které nejsou záznamy, jsou parametry konstruktoru, nikoli vlastnosti. Chybějící značky parametrů v těchto deklaracích kontroluje [SA1611](SA1611.md), nikoli SA1600.

### Přístupnost rozhraní

Nastavení `documentInterfaces` přidává požadavky na dokumentaci deklarací rozhraní a jejich veřejných členů. Výchozí hodnota `true` (nebo `"all"`) vyžaduje dokumentaci i pro interní rozhraní bez ohledu na `documentInternalElements`.

Režim `"exposed"` přidává tento požadavek pouze pro rozhraní přístupná zvenčí a jejich veřejné členy. Používá efektivní přístupnost včetně obsahujících typů. Režim `"none"` (nebo `false`) nepřidává žádný zvláštní požadavek pro rozhraní, ale neruší požadavky obecných nastavení dokumentace. Například `documentInterfaces: false` s `documentExposedElements: true` stále vyžaduje dokumentaci veřejných rozhraní a jejich veřejných členů.

Chcete-li vyžadovat dokumentaci pouze pro kód přístupný zvenčí, nastavte `documentInterfaces` na `"exposed"` (nebo `false`), `documentExposedElements` na `true` a `documentInternalElements` na `false`. Nastavení `documentPrivateElements` a `documentPrivateFields` ponechte na výchozí hodnotě `false`.

### Výchozí členové rozhraní

Členové rozhraní jsou implicitně `public`, pokud není uvedeno jinak. Na výchozí členy rozhraní (metody, vlastnosti, indexery, události atd., které obsahují implementace) se vztahují tato pravidla:

* Veřejné členy rozhraní stále vyžadují dokumentaci, když jsou rozhraní nastavena k dokumentování (výchozí stav).
* Neveřejné členy rozhraní se řídí obecnými nastaveními dokumentace podle efektivní přístupnosti. Soukromé výchozí implementace nevyžadují dokumentaci, pokud `documentPrivateElements` není `true`. Soukromá pole se řídí nastavením `documentPrivateFields`.

Explicitní implementace rozhraní ve třídách nevyžadují samostatnou dokumentaci; dědí dokumentaci z definice rozhraní.

Částečné typy, metody, vlastnosti, indexery, konstruktory a události místo toho hlásí [SA1601](SA1601.md).
U částečných členů stačí zdokumentovat kteroukoli část členu: nezdokumentovaná část není hlášena žádným z pravidel, pokud je zdokumentována jiná část stejného členu, a SA1601 ji hlásí pouze tehdy, není-li zdokumentována žádná část.

## Jak opravit porušení

Chcete-li opravit porušení tohoto pravidla, přidejte nebo vyplňte záhlaví dokumentace prvku.

Následující příklad ukazuje metodu se správným záhlavím dokumentace:

```csharp
/// <summary>
/// Joins a first name and a last name together into a single string.
/// </summary>
/// <param name="firstName">The first name to join.</param>
/// <param name="lastName">The last name to join.</param>
/// <returns>The joined names.</returns>
public string JoinNames(string firstName, string lastName)
{
    return firstName + " " + lastName;
}
```

Následující příklad ukazuje metodu, která dědí dokumentaci z metody v základní třídě:

```csharp
/// <summary>
/// Example base class.
/// </summary>
class Vehicle 
{
  /// <summary>
  /// Accelerates the vehicle.
  /// </summary>
  public virtual void Accelerate()
  {                    
    Console.WriteLine("Vehicle is accelerating");
  }
}

/// <summary>
/// Example derived class.
/// </summary>
class Car : Vehicle
{
  /// <inheritdoc/>
  public override void Accelerate()
  {
    Console.Writeline("Car is accelerating");
  }
}
```

Počínaje jazykem C# 9 mohou přepsání deklarovat kovariantní návratové typy. Dokumentaci lze stále dědit přímo z základního členu pomocí `<inheritdoc/>`:

```csharp
/// <summary>
/// Base factory.
/// </summary>
class WidgetFactory
{
  /// <summary>
  /// Creates a widget.
  /// </summary>
  /// <returns>The newly created <see cref="Widget"/>.</returns>
  public virtual Widget Create() => new Widget();
}

/// <summary>
/// Specialized factory.
/// </summary>
class FancyWidgetFactory : WidgetFactory
{
  /// <inheritdoc/>
  public override FancyWidget Create() => new FancyWidget();
}
```

## Jak potlačit porušení

```csharp
[SuppressMessage("StyleCop.CSharp.DocumentationRules", "SA1600:ElementsMustBeDocumented", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1600 // ElementsMustBeDocumented
#pragma warning restore SA1600 // ElementsMustBeDocumented
```
