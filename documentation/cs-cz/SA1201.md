# SA1201: Elements should appear in the correct order

## Příčina

Prvek v souboru kódu C# není ve správném pořadí vzhledem k ostatním prvkům kódu.

## Popis pravidla

K porušení tohoto pravidla dochází, když prvky kódu v souboru nedodržují standardní schéma uspořádání.

Chcete-li tomuto pravidlu vyhovět, prvky na kořenové úrovni souboru nebo v oboru názvů mají být v tomto pořadí:

* Direktivy aliasu extern
* Direktivy `using`
* Obory názvů
* Delegáti
* Výčty
* Rozhraní
* Struktury
* Třídy

V rámci třídy, struktury nebo rozhraní mají být prvky v tomto pořadí:

* Pole
* Konstruktory
* Finalizéry (destruktory)
* Delegáty
* Události
* Výčty
* Rozhraní
* Bloky rozšíření
* Vlastnosti
* Indexery
* Konverzní operátory
* Operátory
* Metody
* Struktury
* Třídy

> 📝 Pro účely uspořádání se záznamy C# 9 považují za třídy a struktury záznamů C# 10 za struktury.

> 📝 Bloky rozšíření C# 14 (`extension(...) { }`) se řadí jako vlastní typ prvku, za rozhraní a před vlastnosti.

Pořadí druhů členů uvnitř typů lze přizpůsobit pomocí [`orderingRules.memberKindOrder`](Configuration.md#member-kind-order) nebo `stylecop.ordering.memberKindOrder` v EditorConfig.
Neúplný seznam určuje pořadí souvislých skupin uvedených druhů; neuvedené druhy mohou být mezi skupinami, ale ne uvnitř nich.
Pořadí na úrovni souboru a oboru názvů se nemění.
Bez tohoto nastavení nadále platí výše uvedené předdefinované pořadí.

Dodržování standardního schématu uspořádání podle typu prvku může zvýšit čitelnost a udržovatelnost souboru a podpořit opětovné použití kódu.

Při implementaci rozhraní je někdy vhodné seskupit všechny jeho členy vedle sebe. Pokud rozhraní obsahuje prvky různých typů, může to vyžadovat porušení tohoto pravidla. Problém lze vyřešit použitím částečných tříd.

1. Přidejte třídě atribut `partial`, pokud již částečná není.

2. Přidejte druhou částečnou třídu se stejným názvem. Lze ji umístit do stejného souboru pod původní třídu nebo do druhého souboru.

3. Přesuňte dědičnost rozhraní a všechny členy jeho implementace do druhé části třídy.

Například:

```csharp
/// <summary>
/// Represents a customer of the system.
/// </summary>
public partial class Customer
{
    // Contains the main functionality of the class.
}

/// <content>
/// Implements the ICollection class.
/// </content>
public partial class Customer : ICollection
{
    public int Count 
    { 
        get { return this.count; }
    }

    public bool IsSynchronized 
    { 
        get { return false; }
    }

    public object SyncRoot 
    { 
        get { return null; }
    }

    public void CopyTo(Array array, int index)
    {
        throw new NotImplementedException();
    }
}
```

### Řazení členů podle názvu

Přidejte `name` jako poslední položku v `orderingRules.elementOrder`. Název pak rozhoduje o pořadí sousedních členů stejného druhu podle SA1201 ve stejné skupině. SA1201 porovnává názvy ordinálně a rozlišuje velká a malá písmena. Události deklarované jako pole a události s přístupovými metodami patří ke stejnému druhu. Záznamové třídy patří mezi třídy a záznamové struktury mezi struktury. Při výchozím pořadí druhů členů ponechá `static` před `kind` konstanty a pole s výslovným modifikátorem `static` v oddělených skupinách řazených podle názvu. Pokud je `static` za výchozím `kind`, zůstávají třídy a záznamové třídy v samostatných skupinách kvůli pravidlu SA1204. Jestliže první člen skupiny porušuje dřívější kritérium řazení, zůstane při řazení podle názvu na začátku skupiny.

U typů označených pro interoperabilitu s COM se řazení podle názvu nepoužívá. Patří sem i veřejné typy zpřístupněné nastavením viditelnosti pro COM na úrovni sestavení a veřejné typy, na které se vztahuje výslovně nastavené rozhraní třídy COM na úrovni sestavení. Výslovný atribut `[ComVisible(false)]` na sestavení nebo typu má před nastavením rozhraní třídy na úrovni sestavení přednost. U tříd odvozených od `EventSource` se zachovává pořadí deklarací kvůli implicitním identifikátorům událostí.

Inicializátory modulů a vnořené typy, které je obsahují, si zachovávají pořadí a oddělují skupiny řazené podle názvu. U záznamů a typů s pevným rozložením v paměti zůstává zachováno pořadí instančních polí, vlastností a událostí deklarovaných jako pole. Pořadí si zachovávají také instanční členy, které uchovávají data v kontraktech XML označených atributem `[XmlRoot]` nebo `[XmlType]`. Inicializátory vyhodnocované za běhu si zachovávají vzájemné pořadí.

Oprava kódu respektuje hranice vymezené direktivami `#region` a `#endregion` a ponechává na místě vygenerované deklarace i deklarace v oblastech skrytých direktivou `#line hidden`. Jednotlivá i hromadná oprava respektuje direktivu `#pragma warning disable`. Deklarace, u nichž je SA1201 potlačeno místním nebo globálním atributem `SuppressMessage`, se nepřesouvají. Člen bez potlačení se před ně může přesunout.

## Jak opravit porušení

Chcete-li výskyt tohoto porušení opravit, seřaďte prvky v souboru podle výše popsaného pořadí.

Porušení pořadí se hlásí i přes direktivy preprocesoru. Oprava pořadí prvků nepřesouvá členy, pokud by přesun zahrnoval direktivy, protože by mohl změnit podmíněnou kompilaci nebo chování jiných direktiv. Tyto prvky seřaďte ručně při zachování hranic direktiv.

## Jak potlačit porušení

```csharp
[SuppressMessage("StyleCop.CSharp.OrderingRules", "SA1201:ElementsMustAppearInTheCorrectOrder", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1201 // ElementsMustAppearInTheCorrectOrder
#pragma warning restore SA1201 // ElementsMustAppearInTheCorrectOrder
```
