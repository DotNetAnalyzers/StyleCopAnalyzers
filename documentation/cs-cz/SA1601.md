# SA1601: Partial elements should be documented

## Příčina

Částečnému prvku C# chybí hlavička dokumentace.

## Popis pravidla

Syntaxe C# umožňuje vkládat dokumentaci tříd a prvků přímo do kódu pomocí hlaviček dokumentace XML. Úvod k těmto hlavičkám a popis jejich syntaxe najdete v následujícím článku: [https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments](https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments).

K porušení tohoto pravidla dojde, pokud částečnému prvku (prvku s modifikátorem `partial`) zcela chybí hlavička dokumentace nebo je tato hlavička prázdná.
V jazyce C# mohou být modifikátorem `partial` označeny tyto typy prvků: třídy, struktury, rozhraní, záznamy, metody, vlastnosti, indexery, konstruktory a události.

U částečných členů (metod, vlastností, indexerů, konstruktorů a událostí) stačí zdokumentovat kteroukoli část členu.
Kompilátor použije dokumentaci z implementační deklarace, pokud existuje; v opačném případě použije dokumentaci z definiční deklarace.
Nezdokumentovaná část částečného členu je proto hlášena jen tehdy, pokud žádná část daného členu nemá hlavičku dokumentace; v takovém případě jsou hlášeny všechny nezdokumentované části.
Stejně se postupuje u částečných typů: stačí zdokumentovat kteroukoli část typu.

Je-li dokumentace uvedena ve více než jedné části částečné třídy, může se dokumentace obou částí sloučit do jediného zdroje dokumentace. Zvažte například následující dvě části částečné třídy:

```csharp
/// <summary>
/// Documentation for the first part of Class1.
/// </summary>
public partial class Class1
{
}

/// <summary>
/// Documentation for the second part of Class1.
/// </summary>
public partial class Class1
{
}
```

Tyto dvě odlišné části stejné částečné třídy poskytují pro třídu rozdílnou dokumentaci. Při sestavování dokumentace této třídy do sady SDK nástroj pro sestavení dokumentace buď použije pouze jednu část dokumentace třídy a ostatní části ignoruje, nebo v některých případech oba zdroje dokumentace sloučí do řetězce, jako je například: „Dokumentace první části Class1. Dokumentace druhé části Class1.“

Z těchto důvodů může být problematické poskytovat dokumentaci SDK ve více než jedné části částečné třídy. Přesto je vhodné zdokumentovat každou část třídy, aby se zvýšila čitelnost a udržovatelnost kódu, ale StyleCop vyžaduje, aby hlavičku dokumentace obsahovala pouze jedna část třídy.

Tento problém řeší značka `<content>`, která může u částečných tříd nahradit značku `<summary>`. Doporučeným postupem dokumentování částečných tříd je uvést oficiální dokumentaci SDK pro třídu v hlavní části částečné třídy. Tato dokumentace by měla používat standardní značku `<summary>`. Ve všech ostatních částech částečné třídy by se značka `<summary>` neměla uvádět vůbec a měla by být nahrazena značkou `<content>`. Vývojář tak může zdokumentovat všechny části částečné třídy, a přitom soustředit veškerou oficiální dokumentaci SDK pro třídu do jedné její části. Nástroje pro dokumentaci SDK budou značky `<content>` ignorovat.

## Jak opravit porušení

Chcete-li opravit porušení tohoto pravidla, přidejte k prvku hlavičku dokumentace nebo ji vyplňte.

Následující příklad ukazuje dvě části částečné třídy: jedna obsahuje hlavičku `<summary>` a druhá hlavičku `<content>`.

```csharp
/// <summary>
/// Represents a customer in the database.
/// </summary>
public partial class Customer
{
}

/// <content>
/// Contains auto-generated functionality for the Customer class.
/// </content>
public partial class Customer
{
}
```

## Jak potlačit porušení

```csharp
[SuppressMessage("StyleCop.CSharp.DocumentationRules", "SA1601:PartialElementsMustBeDocumented", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1601 // PartialElementsMustBeDocumented
#pragma warning restore SA1601 // PartialElementsMustBeDocumented
```
