:memo: Toto pravidlo je ve StyleCop Analyzers nové a ve StyleCop Classic nebylo k dispozici.

## Příčina

Diagnostické zprávy pro komentáře dokumentace mohou chybět nebo být nesprávné a opravy kódu pro všechny
diagnostické zprávy mohou fungovat nesprávně ve zdrojových souborech obsahujících jakékoli komentáře dokumentace.

## Popis pravidla

K porušení tohoto pravidla dojde, pokud kompilace (projekt) obsahuje jeden nebo více souborů analyzovaných
s hodnotou `DocumentationMode` nastavenou na `None`. K tomu nejčastěji dochází, když je projekt nakonfigurován
tak, aby při sestavení negeneroval soubor dokumentace XML.

SA0001 neznamená, že jsou všechny diagnostické kontroly dokumentace zakázané; pravidla jako SA1600 a SA1604 mohou
nadále hlásit diagnostické zprávy.

Každý projekt by měl být nakonfigurován tak, aby byl k sestavenému výstupu připojen soubor dokumentace XML. Jinak se
nekontroluje sémantika všech komentářů dokumentace a v komentářích se časem pravděpodobně objeví stále více chyb.

## Jak opravit porušení

Chcete-li porušení tohoto pravidla opravit, povolte generování souboru dokumentace XML jako součásti výstupu projektu
přidáním `<GenerateDocumentationFile>true</GenerateDocumentationFile>` do souboru projektu.

**Poznámka:** V některých případech povolení výstupu dokumentace XML způsobí hlášení velkého počtu upozornění
CS1573, CS1591 nebo CS1712. Chcete-li týmům usnadnit vyřešení SA0001 před CS1573, CS1591 a CS1712, zvažte
zakázání těchto upozornění jedním z následujících postupů.

### Potlačení prostřednictvím souborů sad pravidel

CS1573, CS1591 a CS1712 nejsnáze potlačíte úpravou souboru sady pravidel. Závažnost těchto pravidel lze nastavit na
**Hidden** nebo **None**, aby se skryla ve výstupu sestavení. Pokud nastavíte **Hidden**, budou opravy kódu pro tyto
diagnostické informace jako pomůcka při dokumentování fungovat normálně, ale samotná upozornění se nezobrazí.

### Potlačení prostřednictvím souboru projektu

U uživatelů, kteří projekt někdy sestavují se staršími verzemi C# (které nepodporují soubory sad pravidel), lze tato
upozornění potlačit konfigurací elementu `<NoWarn>` v souboru projektu. Jednoduchým způsobem, jak nakonfigurovat
výstup dokumentace (který opraví SA0001) i potlačení CS1573, CS1591 a CS1712, je přidat do souboru projektu
následující skupinu vlastností.

```xml
<PropertyGroup>
  <!--
    Make sure any documentation comments which are included in code get checked for syntax during the build, but do
    not report warnings for missing comments.

    CS1573: Parameter 'parameter' has no matching param tag in the XML comment for 'parameter' (but other parameters do)
    CS1591: Missing XML comment for publicly visible type or member 'Type_or_Member'
  -->
  <DocumentationFile>$(OutputPath)$(AssemblyName).xml</DocumentationFile>
  <NoWarn>$(NoWarn),1573,1591,1712</NoWarn>
</PropertyGroup>
```

## Jak potlačit porušení

Toto upozornění lze potlačit pouze jeho zakázáním v souboru **ruleset** projektu.
