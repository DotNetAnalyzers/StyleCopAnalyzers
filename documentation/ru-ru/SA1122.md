## Причина

В коде C# присутствует пустая строка, записанная как `""`.

## Описание правила

Нарушение этого правила происходит, когда код содержит пустую строку. Например:

```csharp
string s = "";
```

Это приведет к тому, что компилятор внедрит пустую строку в скомпилированный код. Вместо того чтобы включать жестко закодированную пустую строку, используйте статическое свойство **string.Empty**:

```csharp
string s = string.Empty;
```

Правило сообщает обо всех формах пустых строковых литералов, включая дословные, интерполированные и необработанные:

```csharp
string s1 = @"";
string s2 = $"";
string s3 = @$"";
string s4 = """

    """;
string s5 = $"""

    """;
```

О пустой интерполированной строке сообщается только при полном отсутствии содержимого, поэтому `$"{value}"` и `$"text"`
не вызывают диагностику. Пустая интерполированная строка также не вызывает диагностику при преобразовании
в `FormattableString`, `IFormattable` или тип обработчика интерполированных строк, поскольку `string.Empty`
невозможно преобразовать в эти типы.

О строковом литерале UTF-8, таком как `""u8`, не сообщается, поскольку он имеет тип `ReadOnlySpan<byte>`, а не строковый тип.

Нарушение не возникает там, где язык требует константу, независимо от формы её записи: `string.Empty` — это
статическое поле только для чтения, а не константа, поэтому его нельзя использовать вместо литерала.
Это относится к аргументам атрибутов, меткам `case`, константным образцам, значениям параметров по умолчанию,
а также полям и локальным переменным `const`.

## Как исправить нарушения

Чтобы исправить нарушение этого правила, замените жестко закодированную пустую строку на **string.Empty**.

## Как подавить нарушения

```csharp
[SuppressMessage("StyleCop.CSharp.ReadabilityRules", "SA1122:UseStringEmptyForEmptyStrings", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1122 // UseStringEmptyForEmptyStrings
#pragma warning restore SA1122 // UseStringEmptyForEmptyStrings
```
