# SA1201: Элементы должны располагаться в правильном порядке

## Причина

Элемент в файле кода C# расположен в неправильном порядке относительно других элементов.

## Описание правила

Нарушение этого правила возникает, когда элементы кода в файле не следуют стандартному порядку.

Чтобы соблюдать это правило, элементы на верхнем уровне файла или внутри пространства имён должны располагаться в следующем порядке:

* Директивы extern alias
* Директивы using
* Пространства имён
* Делегаты
* Перечисления
* Интерфейсы
* Структуры
* Классы

Внутри класса, структуры или интерфейса элементы должны располагаться в следующем порядке:

* Поля
* Конструкторы
* Финализаторы (деструкторы)
* Делегаты
* События
* Перечисления
* Интерфейсы
* Блоки расширений
* Свойства
* Индексаторы
* Операторы преобразования
* Операторы
* Методы
* Структуры
* Классы

> 📝 При упорядочивании записи C# 9 рассматриваются как классы, а структуры-записи C# 10 — как структуры.

> 📝 Блоки расширений C# 14 (`extension(...) { }`) рассматриваются как отдельный вид элементов и располагаются после интерфейсов, но перед свойствами.

Порядок видов членов внутри типов можно настроить с помощью [`orderingRules.memberKindOrder`](Configuration.md#member-kind-order) или `stylecop.ordering.memberKindOrder` в EditorConfig.
Неполный список задаёт порядок непрерывных групп указанных видов; неуказанные виды могут находиться между группами, но не внутри них.
Порядок на уровне файла и пространства имён не меняется.
Без этого параметра по-прежнему применяется стандартный порядок, описанный выше.

Соблюдение стандартного порядка, основанного на виде элемента, повышает читаемость и удобство сопровождения файла, а также способствует повторному использованию кода.

При реализации интерфейса иногда желательно сгруппировать все его члены рядом друг с другом. Если интерфейс содержит элементы разных видов, это может потребовать нарушения данного правила. Эту проблему можно решить с помощью частичных классов.

1. Добавьте к классу модификатор partial, если класс ещё не является частичным.

2. Добавьте второй частичный класс с тем же именем. Его можно разместить в том же файле непосредственно под исходным классом или в отдельном файле.

3. Перенесите указание реализуемого интерфейса и все члены его реализации во вторую часть класса.

Например:

```csharp
/// <summary>
/// Represents a customer of the system.
/// </summary>
public partial class Customer
{
    // Contains the main functionality of the class.
}

/// <content>
/// Implements the ICollection class.
/// </content>
public partial class Customer : ICollection
{
    public int Count 
    { 
        get { return this.count; }
    }

    public bool IsSynchronized 
    { 
        get { return false; }
    }

    public object SyncRoot 
    { 
        get { return null; }
    }

    public void CopyTo(Array array, int index)
    {
        throw new NotImplementedException();
    }
}
```

### Упорядочивание членов по имени

Добавьте `name` в конец списка `orderingRules.elementOrder`, чтобы имя определяло порядок соседних членов одного вида объявления в одной группе. SA1201 сравнивает имена по числовым значениям символов с учётом регистра.

Упорядочивание по имени отключено для типов, помеченных для взаимодействия с COM, в том числе для открытых типов, доступных COM благодаря настройке видимости на уровне сборки. Инициализаторы модулей и содержащие их вложенные типы сохраняют свой порядок и разделяют группы, упорядочиваемые по имени. Для записей и типов с фиксированной раскладкой в памяти сохраняется порядок полей, свойств и событий в форме поля, относящихся к экземпляру. Инициализаторы, выполняемые во время работы программы, сохраняют взаимный порядок, а исправление кода учитывает границы, заданные директивами `#region` и `#endregion`. При исправлении всех нарушений SA1201 сортировка по имени сохраняет порядок членов в областях, где директива `#pragma warning disable` подавляет предупреждение SA1201.

## Как исправить нарушения

Чтобы исправить нарушение, расположите элементы файла в описанном выше порядке.

Нарушения порядка по-прежнему обнаруживаются через границы директив препроцессора. Исправление порядка элементов не перемещает члены, если перемещение затрагивает директивы, поскольку это может изменить условную компиляцию или действие других директив. Переставьте такие элементы вручную, сохранив границы директив.

## Как подавить нарушения

```csharp
[SuppressMessage("StyleCop.CSharp.OrderingRules", "SA1201:ElementsMustAppearInTheCorrectOrder", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1201 // ElementsMustAppearInTheCorrectOrder
#pragma warning restore SA1201 // ElementsMustAppearInTheCorrectOrder
```
