## Причина

У частичного элемента C# отсутствует комментарий документации.

## Описание правила

Синтаксис C# позволяет включать документацию для классов и других элементов непосредственно в код с помощью XML-комментариев документации. Введение в эти комментарии и описание их синтаксиса приведены в статье: [https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments](https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments).

Нарушение возникает, если у частичного элемента (элемента с модификатором partial) полностью отсутствует комментарий документации или этот комментарий пуст.
В C# модификатор partial может применяться к классам, структурам, интерфейсам, записям, методам, свойствам, индексаторам, конструкторам и событиям.

Для частичных членов (методов, свойств, индексаторов, конструкторов и событий) достаточно документировать любую одну часть.
Компилятор использует документацию реализующего объявления, если она есть, а иначе — документацию определяющего объявления.
Поэтому нарушение для недокументированной части частичного члена регистрируется только тогда, когда ни у одной его части нет комментария документации. В этом случае нарушение регистрируется для каждой недокументированной части.
К частичным типам это не относится: каждая часть частичного типа должна иметь комментарий документации.

Если документация присутствует в нескольких частях частичного класса, документация этих частей может объединяться в единый текст. Например, рассмотрим следующие две части частичного класса:

```csharp
/// <summary>
/// Documentation for the first part of Class1.
/// </summary>
public partial class Class1
{
}

/// <summary>
/// Documentation for the second part of Class1.
/// </summary>
public partial class Class1
{
}
```

Эти две части одного частичного класса предоставляют разную документацию для класса. При включении документации класса в SDK средство создания документации либо выберет только одну часть, проигнорировав остальные, либо в некоторых случаях объединит оба источника в строку вида: «Documentation for the first part of Class1. Documentation for the second part of Class1.»

Поэтому размещение документации SDK в нескольких частях частичного класса может создавать проблемы. Однако для удобства чтения и сопровождения кода всё же рекомендуется документировать каждую часть класса, и StyleCop требует, чтобы у каждой части был комментарий документации.

Эту проблему решает тег `<content>`, которым можно заменить тег `<summary>` для частичных классов. Рекомендуется размещать официальную документацию SDK для класса в основной части частичного класса, используя стандартный тег `<summary>`. Во всех остальных частях следует полностью исключить тег `<summary>` и заменить его тегом `<content>`. Это позволяет документировать все части частичного класса, сохраняя всю официальную документацию SDK в одной части. Средства создания документации SDK игнорируют теги `<content>`.

## Как исправить нарушение

Добавьте или заполните комментарий документации для элемента.

Например, ниже показаны две части частичного класса: одна с комментарием `<summary>`, а другая с комментарием `<content>`.

```csharp
/// <summary>
/// Represents a customer in the database.
/// </summary>
public partial class Customer
{
}

/// <content>
/// Contains auto-generated functionality for the Customer class.
/// </content>
public partial class Customer
{
}
```

## Как подавить нарушение

```csharp
[SuppressMessage("StyleCop.CSharp.DocumentationRules", "SA1601:PartialElementsMustBeDocumented", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1601 // PartialElementsMustBeDocumented
#pragma warning restore SA1601 // PartialElementsMustBeDocumented
```
