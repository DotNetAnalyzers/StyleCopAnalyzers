## Причина

Тег `<summary>` или `<content>` в комментарии документации элемента кода C# отсутствует или пуст.

## Описание правила

Синтаксис C# позволяет включать документацию для классов и других элементов непосредственно в код с помощью XML-комментариев документации.
Введение в эти комментарии и описание их синтаксиса приведены в статье: [https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments](https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments).

Нарушение возникает, если в комментарии документации частичного элемента (элемента с модификатором partial) отсутствует тег `<summary>` или `<content>` либо такой тег пуст и не содержит описания элемента.
В C# модификатор partial может применяться к классам, методам, свойствам, индексаторам, конструкторам и событиям.

Если документация присутствует в нескольких частях частичного класса, документация этих частей может объединяться в единый текст. Например, рассмотрим следующие две части частичного класса:

```csharp
/// <summary>
/// Documentation for the first part of Class1.
/// </summary>
public partial class Class1
{
}

/// <summary>
/// Documentation for the second part of Class1.
/// </summary>
public partial class Class1
{
}
```

Эти две части одного частичного класса предоставляют разную документацию для класса.
При включении документации класса в SDK средство создания документации либо выберет только одну часть, проигнорировав остальные,
либо в некоторых случаях объединит оба источника в строку вида: «Documentation for the first part of Class1. Documentation for the second part of Class1.»

Поэтому размещение документации SDK в нескольких частях частичного класса может создавать проблемы.
Однако для удобства чтения и сопровождения кода всё же рекомендуется документировать каждую часть класса, и StyleCop требует, чтобы у каждой части был комментарий документации.

Эту проблему решает тег `<content>`, которым можно заменить тег `<summary>` для частичных классов.
Рекомендуется размещать официальную документацию SDK для класса в основной части частичного класса.
Эту документацию следует писать с помощью стандартного тега `<summary>`. Во всех остальных частях следует полностью исключить тег `<summary>` и заменить его тегом `<content>`.
Это позволяет документировать все части частичного класса, сохраняя всю официальную документацию SDK в одной части.
Средства создания документации SDK игнорируют теги `<content>`.

## Как исправить нарушение

Добавьте тег `<summary>` или `<content>` и заполните его описанием элемента кода.

В следующем примере показан частичный класс с заполненным тегом `<summary>`.

```csharp
/// <summary>
/// Represents a customer in the database.
/// </summary>
public partial class Customer
{
}
```

## Как подавить нарушение

```csharp
[SuppressMessage("StyleCop.CSharp.DocumentationRules", "SA1605:PartialElementDocumentationMustHaveSummary", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1605 // PartialElementDocumentationMustHaveSummary
#pragma warning restore SA1605 // PartialElementDocumentationMustHaveSummary
```
