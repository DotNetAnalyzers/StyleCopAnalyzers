## Причина

Элемент в файле кода C# расположен в неправильном порядке по уровню доступа относительно других элементов кода.

## Описание правила

Нарушение этого правила возникает, когда элементы кода в файле не следуют стандартному порядку, основанному на уровне доступа.

Чтобы соблюдать это правило, соседние элементы одного вида должны располагаться в следующем порядке по уровню доступа:

* public
* internal
* protected internal
* protected
* private protected
* private

:memo: Для целей этого правила статические конструкторы и явно реализованные члены интерфейса считаются *public*.

Соблюдение стандартного порядка по уровню доступа повышает читаемость и удобство сопровождения файла, а также помогает быстрее определить открытый интерфейс класса.

### Интерфейсы и члены интерфейсов по умолчанию

Члены интерфейсов по умолчанию (включая члены с реализацией и статические члены интерфейсов) следуют тому же порядку по уровню доступа, что и члены классов. Внутри интерфейса члены `public` должны предшествовать членам `internal`, `protected internal`, `protected`, `private protected` и `private`.

### Записи и первичные конструкторы

Записи (включая позиционные записи) и структуры-записи следуют тем же правилам упорядочивания, что и классы и структуры. Параметры первичного конструктора, которые становятся свойствами, не изменяют ожидаемый порядок по уровню доступа для остальных членов.

## Как исправить нарушения

Чтобы исправить нарушение, расположите элементы файла в описанном выше порядке.

## Как подавить нарушения

```csharp
[SuppressMessage("StyleCop.CSharp.OrderingRules", "SA1202:ElementsMustBeOrderedByAccess", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1202 // ElementsMustBeOrderedByAccess
#pragma warning restore SA1202 // ElementsMustBeOrderedByAccess
```
