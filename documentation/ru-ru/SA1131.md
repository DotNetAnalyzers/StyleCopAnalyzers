:memo: Это правило является новым для **StyleCop Analyzers**, и его не было в **StyleCop Classic**.

## Причина

Сравнение было произведено между переменной и литеральным значением или константой, и переменная оказалась в правой части выражения.

## Описание правила

Нарушение этого правила происходит в том случае, если код содержит сравнение между литеральным значением или константой и значением переменной, и переменная оказалась в правой части выражения.

Например, в следующем коде показан один из часто встречающихся случаев:

```csharp
public void Method(string value)
{
    if (null == value) // SA1131
    {
        throw new ArgumentNullException(nameof(value));
    }
}
```

Здесь под *литеральным или константным значением* понимается любое из следующих:

* Числовой литерал, такой как `1`, `0.0f` или `5.0m`
* Строковый литерал
* `null`
* `default(T)` (для любого типа `T`)
* Любое выражение, которое оценивается в постоянное значение во время компиляции
* Ссылка на `static readonly` поле, такое как `IntPtr.Zero`.
* Образец сопоставления.

Значение *переменной* - это любое выражение, которое не считается литералом или константным значением.

*Сравнение* - это бинарное выражение, использующее один из следующих операторов.

* `==`
* `!=`
* `<`
* `>`
* `<=`
* `>=`

## Как исправить нарушение

Чтобы исправить нарушение этого правила, измените порядок следования операндов при сравнении.

## Как подавить нарушения

```csharp
public void Method(string value)
{
#pragma warning disable SA1131 // Use readable conditions
    if (null == value)
#pragma warning restore SA1131 // Use readable conditions
    {
        throw new ArgumentNullException(nameof(value));
    }
}
```
