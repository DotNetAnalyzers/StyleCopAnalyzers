## Причина

Открывающая или закрывающая фигурная скобка в инструкции, элементе или выражении C# не размещена на отдельной строке.

> :memo: Поведение этого правила может изменяться в зависимости от значения свойства `allowDoWhileOnClosingBrace` в **stylecop.json**. Дополнительные сведения см. в [Configuration.md](Configuration.md#layout-rules).

## Описание правила

Нарушение этого правила возникает, когда открывающая или закрывающая фигурная скобка в инструкции, элементе или выражении не размещена на отдельной строке. Например:

```csharp
public object Method()
{
    lock (this) {
        return this.value;
    }
}
```

При проверке этого кода StyleCop сообщает о нарушении, поскольку открывающая скобка инструкции lock находится на одной строке с ключевым словом lock, а не на отдельной строке, как в следующем примере:

```csharp
public object Method()
{
    lock (this) 
    {
        return this.value;
    }
}
```

Нарушение также возникает, если закрывающая скобка находится на одной строке с другим кодом. Например:

```csharp
public object Method()
{
    lock (this) 
    {
        return this.value; }
}
```

Начиная с C# 8.0 это правило также применяется к скобкам в выражениях switch и образцах свойств. Если ветви выражения или содержимое образца занимают несколько строк, скобки `{` и `}` выражения switch или образца свойств должны располагаться на отдельных строках.

## Как исправить нарушения

Чтобы исправить нарушение этого правила, разместите открывающую и закрывающую фигурные скобки на отдельных строках, не содержащих другого кода, кроме комментариев.

## Как подавить нарушения

```csharp
[SuppressMessage("StyleCop.CSharp.LayoutRules", "SA1500:BracesForMultiLineStatementsMustNotShareLine", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1500 // BracesForMultiLineStatementsMustNotShareLine
#pragma warning restore SA1500 // BracesForMultiLineStatementsMustNotShareLine
```
