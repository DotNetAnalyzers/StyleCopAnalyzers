:memo: Это правило является новым для **StyleCop Analyzers**, и его не было в **StyleCop Classic**.

## Причина

Тип значений был создан с использованием синтаксиса `new T()`.

## Описание правила

Нарушение этого правила происходит, когда тип значения `T` построен с использованием синтаксиса `new T()`. Чтобы создать экземпляр типа значения по умолчанию, используйте вместо этого эквивалентный синтаксис `default(T)`.

Например, следующий код приведет к нарушению этого правила:

```csharp
ImmutableArray<int> array = new ImmutableArray<int>();
```

Хотя кажется, что приведённый выше код создаёт новый неизменяемый массив, готовый к использованию, в действительности переменной `array` присвоен экземпляр `ImmutableArray<int>` со значением по умолчанию, и почти любая попытка использовать переменную приведёт к `NullReferenceException`. Чтобы избежать путаницы с поведением ссылочных типов, экземпляры типов значений со значением по умолчанию всегда следует создавать с помощью синтаксиса `default(T)`.

> :memo: Это предложение относится только к различию между `default(T)` и `new T()`. Другие значения по умолчанию, включая `CancellationToken.None`, `0`, `0.0f`, `IntPtr.Zero` и `RegexOptions.None`, *не* будут выдавать предупреждение.

## Как исправить нарушения

Чтобы исправить нарушение этого правила, замените синтаксис `new T()` на эквивалентный синтаксис `default(T)`.

Для целых чисел с размером, зависящим от платформы, созданных через `new nint()`/`new nuint()`, исправление кода
использует `IntPtr.Zero`/`UIntPtr.Zero` только в проектах, где это имеет тот же смысл: в C# 11 при наличии
поддержки таких целых чисел в среде выполнения (например, .NET 7 или более поздней версии).
В остальных случаях исправление использует `default(nint)`/`default(nuint)`, чтобы сохранить поведение исходного кода.

## Как подавить нарушения

```csharp
#pragma warning disable SA1129 // Do not use default value type constructor
IntPtr zero = new IntPtr();
#pragma warning restore SA1129 // Do not use default value type constructor
```
