## Причина

У элемента кода C# отсутствует комментарий документации.

## Описание правила

Синтаксис C# позволяет включать документацию для классов и других элементов непосредственно в код с помощью XML-комментариев документации. Введение в эти комментарии и описание их синтаксиса приведены в статье: [https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments](https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments).

Нарушение возникает, если у элемента полностью отсутствует комментарий документации или этот комментарий пуст. В C# комментарии документации могут иметь следующие элементы: классы, конструкторы, делегаты, перечисления, события, финализаторы, индексаторы, интерфейсы, методы, свойства, записи и структуры.

### Записи и первичные конструкторы

К классам-записям и структурам-записям предъявляются те же требования, что и к классам и структурам. Позиционные параметры объявления записи становятся свойствами; при документировании открытой записи добавьте теги `<param>` для этих параметров в дополнение к тексту `<summary>` для самой записи.

### Члены интерфейсов с реализацией по умолчанию

Члены интерфейсов неявно имеют доступность `public`, если не указано иное. Для членов интерфейсов с реализацией по умолчанию (методов, свойств, индексаторов, событий и т. д., содержащих реализацию) действуют следующие правила:

* Открытые члены интерфейсов по-прежнему требуют документации, если включено документирование интерфейсов (настройка по умолчанию).
* Неоткрытые члены интерфейсов (например, реализации по умолчанию с доступностью `private`) подчиняются настройке `documentPrivateElements`. Если `documentPrivateElements` имеет значение `false` (по умолчанию), документация для этих членов не требуется.

Явные реализации интерфейсов в классах не требуют отдельной документации: они наследуют документацию из определения интерфейса.

Для частичных типов, методов, свойств, индексаторов, конструкторов и событий вместо этого используется правило [SA1601](SA1601.md).
Для частичных членов достаточно документировать любую одну часть: ни одно из этих правил не сообщает о недокументированной части, если другая часть того же члена документирована. SA1601 сообщает о нарушении только тогда, когда не документирована ни одна часть.

## Как исправить нарушение

Добавьте или заполните комментарий документации для элемента.

В следующем примере показан метод с корректным комментарием документации:

```csharp
/// <summary>
/// Joins a first name and a last name together into a single string.
/// </summary>
/// <param name="firstName">The first name to join.</param>
/// <param name="lastName">The last name to join.</param>
/// <returns>The joined names.</returns>
public string JoinNames(string firstName, string lastName)
{
    return firstName + " " + lastName;
}
```

Следующий пример показывает метод, наследующий документацию метода базового класса:

```csharp
/// <summary>
/// Example base class.
/// </summary>
class Vehicle 
{
  /// <summary>
  /// Accelerates the vehicle.
  /// </summary>
  public virtual void Accelerate()
  {                    
    Console.WriteLine("Vehicle is accelerating");
  }
}

/// <summary>
/// Example derived class.
/// </summary>
class Car : Vehicle
{
  /// <inheritdoc/>
  public override void Accelerate()
  {
    Console.Writeline("Car is accelerating");
  }
}
```

Начиная с C# 9, переопределяемые члены могут объявлять ковариантные возвращаемые типы. Документацию по-прежнему можно наследовать непосредственно от базового члена с помощью `<inheritdoc/>`:

```csharp
/// <summary>
/// Base factory.
/// </summary>
class WidgetFactory
{
  /// <summary>
  /// Creates a widget.
  /// </summary>
  /// <returns>The newly created <see cref="Widget"/>.</returns>
  public virtual Widget Create() => new Widget();
}

/// <summary>
/// Specialized factory.
/// </summary>
class FancyWidgetFactory : WidgetFactory
{
  /// <inheritdoc/>
  public override FancyWidget Create() => new FancyWidget();
}
```

## Как подавить нарушение

```csharp
[SuppressMessage("StyleCop.CSharp.DocumentationRules", "SA1600:ElementsMustBeDocumented", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1600 // ElementsMustBeDocumented
#pragma warning restore SA1600 // ElementsMustBeDocumented
```
