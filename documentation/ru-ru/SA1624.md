## Причина

Текст документации в теге `<summary>` свойства C# учитывает все методы доступа свойства, хотя один из них имеет ограниченную доступность.

## Описание правила

Синтаксис C# позволяет включать документацию для классов и других элементов непосредственно в код с помощью XML-комментариев документации. Введение в эти комментарии и описание их синтаксиса приведены в статье: [https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments](https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/xmldoc/xml-documentation-comments).

Нарушение возникает, если один из методов доступа свойства (обычно set) имеет ограниченную доступность, но краткое описание свойства всё ещё упоминает оба метода доступа.

Обычно краткое описание свойства должно начинаться с формулировки, описывающей предоставляемые свойством методы доступа. Если у свойства есть только get, описание должно начинаться со слова «Gets» («Получает»). Если есть только set — со слова «Sets» («Задаёт»). Если свойство предоставляет и get, и set, описание должно начинаться с «Gets or sets» («Получает или задаёт»).

Однако если методу доступа задан более ограниченный уровень доступности, чем самому свойству, этот метод не следует упоминать в кратком описании. Это относится и к методам доступа `init` с ограниченной доступностью.

Иногда неочевидно, действительно ли set менее доступен, чем get. Например, если открытое свойство находится в классе с доступностью internal, а set также имеет доступность internal, фактически get и set имеют одинаковый уровень доступности. В таком случае краткое описание должно упоминать оба метода доступа, поскольку их фактическая доступность одинакова.

В некоторых случаях set свойства может иметь более ограниченную доступность, чем get. Например:

```csharp
/// <summary>
/// Gets the name of the customer. 
/// </summary>
public string Name
{
    get { return this.name; }
    private set { this.name = value; }
}
```

В этом примере set имеет доступность private, то есть к нему могут обращаться только члены содержащего его класса. Метод get наследует доступность свойства, поэтому к нему может обращаться любой вызывающий код: свойство имеет доступность public.

В таком случае краткое описание документации не должно упоминать set, поскольку этот метод недоступен внешнему вызывающему коду.

StyleCop использует ряд правил, чтобы определить, когда следует упоминать set в кратком описании свойства. В общем случае set необходимо упоминать, если он доступен тому же кругу вызывающего кода, что и get, либо если он доступен внешним или производным классам.

Конкретные условия включения set в краткое описание свойства:

1. Метод set имеет тот же уровень доступности, что и get. Например:

    ```csharp
    /// <summary>
    /// Gets or sets the name of the customer. 
    /// </summary>
    protected string Name
    {
        get { return this.name; }
        set { this.name = value; }
    }
    ```

2. Свойство доступно только внутри сборки, и метод set также имеет доступность internal. Например:

    ```csharp
    internal class Class1
    {
        /// <summary>
        /// Gets or sets the name of the customer. 
        /// </summary>
        protected string Name
        {
            get { return this.name; }
            internal set { this.name = value; }
        }
    }

    internal class Class1
    {
        public class Class2
        {
            /// <summary>
            /// Gets or sets the name of the customer. 
            /// </summary>
            public string Name
            {
                get { return this.name; }
                internal set { this.name = value; }
            }
        }
    }
    ```

3. Свойство имеет доступность private или находится внутри класса с доступностью private, а метод set имеет любой модификатор доступа, кроме private. В следующем примере модификатор доступа set не влияет на фактическую доступность, поскольку set находится внутри закрытого класса и недоступен классам за пределами Class1. Фактически set имеет тот же уровень доступности, что и get.

    ```csharp
    public class Class1
    {
        private class Class2
        {
            public class Class3
            {
                /// <summary>
                /// Gets or sets the name of the customer. 
                /// </summary>
                public string Name
                {
                    get { return this.name; }
                    internal set { this.name = value; }
                }
            }
        }
    }
    ```

4. Если set имеет доступность protected или protected internal, его всегда следует упоминать в документации. Такой метод set всегда доступен классу, наследующему класс со свойством.

    ```csharp
    internal class Class1
    {
        public class Class2
        {
            /// <summary>
            /// Gets or sets the name of the customer. 
            /// </summary>
            internal string Name
            {
                get { return this.name; }
                protected set { this.name = value; }
            }
        }

        private class Class3 : Class2
        {
            public Class3(string name) { this.Name = name; }
        }
    }
    ```

## Как исправить нарушение

Измените краткое описание свойства, удалив формулировку, относящуюся к методу доступа с ограниченной доступностью.

## Как подавить нарушение

```csharp
[SuppressMessage("StyleCop.CSharp.DocumentationRules", "SA1624:PropertySummaryDocumentationMustOmitSetAccessorWithRestrictedAccess", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1624 // PropertySummaryDocumentationMustOmitSetAccessorWithRestrictedAccess
#pragma warning restore SA1624 // PropertySummaryDocumentationMustOmitSetAccessorWithRestrictedAccess
```
