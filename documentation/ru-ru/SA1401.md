## Причина

Поле в классе C# имеет модификатор доступа, отличный от private.

## Описание правила

Нарушение этого правила возникает, когда полю класса предоставляется доступ, отличный от private. Для удобства сопровождения доступ к полям извне класса всегда следует предоставлять через свойства, а сами поля всегда объявлять как private. Это позволяет со временем изменять внутреннюю реализацию свойства, не меняя интерфейс класса.

Поля в структурах C# могут иметь любой уровень доступа.

Статические поля readonly не вызывают нарушения. Такие поля часто представляют постоянное значение, когда ключевое слово `const` использовать нельзя, поэтому для них сделано исключение. Для полей экземпляра модификатор readonly сам по себе исключения не создаёт: чтобы соблюдать правило, они всё равно должны быть private.

Модификатор `readonly` для членов структур C# 8 (методов, свойств, индексаторов и событий) не влияет на это правило, поскольку оно рассматривает только поля.

## Как исправить нарушения

Чтобы исправить нарушение этого правила, сделайте поле private и добавьте свойство для доступа к нему извне класса.

## Как подавить нарушения

```csharp
[SuppressMessage("StyleCop.CSharp.MaintainabilityRules", "SA1401:FieldsMustBePrivate", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1401 // FieldsMustBePrivate
#pragma warning restore SA1401 // FieldsMustBePrivate
```
