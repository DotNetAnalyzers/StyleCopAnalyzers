## Причина

Директива using языка C# размещена вне элемента пространства имён.

> :memo: Поведение этого правила может изменяться в зависимости от значения свойства `usingDirectivesPlacement` в **stylecop.json**. Дополнительные сведения см. в [Configuration.md](Configuration.md#using-directives).

## Описание правила

Нарушение этого правила возникает, когда директива using или директива using, объявляющая псевдоним, размещена вне элемента пространства имён, за исключением файлов, которые вообще не содержат пространств имён.

> :memo: При использовании инструкций верхнего уровня C# 9 все директивы `using` должны предшествовать исполняемому коду. Если файл содержит инструкции верхнего уровня (и, следовательно, не содержит объявления пространства имён), директивы using в начале файла считаются корректными независимо от значения параметра `usingDirectivesPlacement`.

> :memo: Глобальные директивы using (C# 10) всегда находятся вне пространств имён; при размещении внутри пространства имён компилятор выдаёт ошибку. SA1200 не сообщает о нарушениях, связанных с расположением глобальных директив using.

Например, следующий код приводит к двум нарушениям этого правила.

```csharp
using System;
using Guid = System.Guid;

namespace Microsoft.Sample
{
    public class Program
    {
    }
}
```

Однако следующий код не приводит ни к одному нарушению этого правила:

```csharp
namespace Microsoft.Sample
{
    using System;
    using Guid = System.Guid;
 
    public class Program
    {
    }
}
```

Между размещением директив using внутри пространства имён и за его пределами есть неочевидные различия, в частности:

1. Размещение директив using, объявляющих псевдонимы, внутри пространства имён устраняет неоднозначность для компилятора при наличии конфликтующих типов.

2. Если в одном файле определено несколько пространств имён, размещение директив using внутри каждого из них ограничивает область действия ссылок и псевдонимов.

### 1. Устранение неоднозначности типов

Рассмотрим следующий код, в котором директива using, объявляющая псевдоним, находится вне пространства имён. Код создаёт новый класс *Guid*, а также определяет псевдоним *Guid* для типа *System.Guid*. Затем создаётся экземпляр типа *Guid*:

```csharp
using Guid = System.Guid;
 
namespace Microsoft.Sample
{
    public class Guid
    {
        public Guid(string s)
        {
        }
    }

    public class Program
    {
        public static void Main(string[] args)
        {
            Guid g = new Guid("hello");
        }
    }
}
```

Этот код компилируется без ошибок. Однако неясно, экземпляр какого именно типа *Guid* создаётся. Если переместить директиву using внутрь пространства имён, как показано ниже, возникнет ошибка компиляции:

```csharp
namespace Microsoft.Sample
{
    using Guid = System.Guid;

    public class Guid
    {
        public Guid(string s)
        {
        }
    }

    public class Program
    {
        public static void Main(string[] args)
        {
            Guid g = new Guid("hello");
        }
    }
}
```

Компиляция завершается следующей ошибкой в строке `Guid g = new Guid("hello");`:

> CS0576: Пространство имён 'Microsoft.Sample' содержит определение, конфликтующее с псевдонимом 'Guid'

Код создаёт псевдоним *Guid* для типа *System.Guid*, а также собственный тип *Guid* с совместимой сигнатурой конструктора. Затем код создаёт экземпляр типа *Guid*. Для этого компилятор должен выбрать одно из двух разных определений *Guid*. Когда директива using с псевдонимом находится вне пространства имён, компилятор выбирает локальное определение *Guid* из текущего пространства имён и полностью игнорирует псевдоним, объявленный снаружи. К сожалению, при чтении кода это неочевидно.

Если же директива using с псевдонимом находится внутри пространства имён, компилятор вынужден выбирать между двумя конфликтующими типами *Guid*, определёнными в одном пространстве имён. Оба типа предоставляют подходящий конструктор. Компилятор не может сделать выбор и сообщает об ошибке.

Размещение директивы using с псевдонимом вне пространства имён — нежелательная практика: в подобных ситуациях оно создаёт неоднозначность, и становится неясно, какой тип используется на самом деле. Это может привести к ошибке, причину которой трудно установить.

Размещение директив using с псевдонимами внутри пространства имён устраняет этот источник ошибок.

### 2. Несколько пространств имён

Размещать несколько пространств имён в одном файле обычно не рекомендуется. Но если это всё же необходимо, лучше размещать все директивы using внутри соответствующих пространств имён, а не глобально в начале файла. Это чётко ограничивает их область действия и помогает избежать описанного выше поведения.

Важно учитывать, что при переносе директив using снаружи внутрь пространства имён необходимо убедиться, что семантика существующего кода не меняется. Как объяснялось выше, размещение директив using с псевдонимами внутри пространства имён позволяет компилятору выбирать между конфликтующими типами иначе, чем при размещении этих директив снаружи.

## Как исправить нарушения

Чтобы исправить нарушение этого правила, переместите все директивы using и директивы using с псевдонимами внутрь пространства имён.

## Как подавить нарушения

```csharp
[SuppressMessage("StyleCop.CSharp.OrderingRules", "SA1200:UsingDirectivesMustBePlacedWithinNamespace", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1200 // UsingDirectivesMustBePlacedWithinNamespace
#pragma warning restore SA1200 // UsingDirectivesMustBePlacedWithinNamespace
```
