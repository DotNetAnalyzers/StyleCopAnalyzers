## Причина

Имя файла кода C# не соответствует первому типу, объявленному в файле. Для обобщённых типов вида
`Class1<T>` файл должен называться `Class1{T}.cs` или ``Class1`1.cs`` в зависимости от настройки `fileNamingConvention`.
Дополнительные сведения приведены в [Configuration.md](Configuration.md).

Частичные классы игнорируются.

## Описание правила

Нарушение возникает, если имя файла C# не содержит имени первого типа в файле.
Например, рассмотрим исходный файл C# с именем Class1.cs и следующим кодом:

```csharp
public class Class2
{
}
```

Здесь возникает нарушение, поскольку имя файла не содержит правильного имени первого типа в файле.
Содержимое файла должно выглядеть так:

```csharp
public class Class1
{
}
```

Модификатор `readonly` у типа (например, `readonly struct`) или у членов первого типа (например, членов структуры
только для чтения в C# 8) не меняет ожидаемого имени файла. Анализатор по-прежнему использует идентификатор
первого нечастичного типа, поэтому тип, объявленный как `public readonly struct Point`, должен находиться в `Point.cs`.

При определении имени файла escape-последовательности Unicode в идентификаторе заменяются соответствующими символами. Например,
`class Name\u0065 { }` должен находиться в `Namee.cs`, а не в файле, имя которого содержит escape-последовательность.
Аналогично, префикс `@` дословного идентификатора не входит в ожидаемое имя файла.

## Как исправить нарушение

Переименуйте файл в соответствии с именем первого типа в файле.

## Как подавить нарушение

```csharp
[SuppressMessage("StyleCop.CSharp.DocumentationRules", "SA1649:FileNameMustMatchTypeName", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1649 // SA1649FileNameMustMatchTypeName
#pragma warning restore SA1649 // SA1649FileNameMustMatchTypeName
```
