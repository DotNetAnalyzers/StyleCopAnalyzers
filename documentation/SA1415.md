# SA1415: Do not use public on members of internal types

:bulb: This rule is disabled by default.

## Cause

A member of a type that is effectively internal or private is declared `public`.

## Rule description

A violation of this rule occurs when a member is declared `public` but its containing type is not visible outside the assembly. A `public` member of an `internal` or `private` type is not part of the assembly's public API; it is only as visible as the type itself. Reviewers who watch for new public API often have to look past these members.

This rule reports an explicit `public` modifier on a member of a type whose effective accessibility is `internal`, `private`, or `private protected`. That includes members of:

* top-level `internal` types
* `private` or `internal` nested types
* `public` or `protected` types nested in an `internal` type, which are themselves effectively internal
* `private protected` nested types (including those nested in a public type), which are not visible outside the assembly
* `file` types

The following are not reported:

* Members of types that are effectively `public`, `protected`, or `protected internal` (these can be visible outside the assembly)
* Members that implement an interface or override a base member, which must remain `public`, including every part of a partial method, property, or event
* A member of a base type that a derived type uses as an implicit implementation of an interface member
* User-defined operators and conversions, which the language requires to be `public`
* `GetEnumerator`, `MoveNext`, and `Current` when pattern-based `foreach` requires them to be `public`, and `GetAsyncEnumerator`, `MoveNextAsync`, and `Current` when `await foreach` requires them to be `public`. This includes internal collection and enumerator types that do not implement the collection interfaces, members inherited through an interface such as `IEnumerator<T>`, and a member on a base enumerator that a derived enumerator completes, including an overridden `virtual` `MoveNext` or `Current` (`MoveNext` on the base with `Current` on the derived type, or the reverse). It also includes `GetEnumerator` or `GetAsyncEnumerator` whose return type is a type parameter constrained to an enumerator type, and a public extension `GetEnumerator` or `GetAsyncEnumerator` declared in the compilation. The extension receiver is not an extra parameter. `MoveNextAsync` is recognized when its result is awaitable through an instance `GetAwaiter` or through an extension `GetAwaiter` declared in the compilation
* Instance fields, properties with a public or omitted `set` or `init` accessor, and constructors on a type derived from `System.Attribute`. Named arguments such as `[A(Value = 1)]` and positional arguments such as `[A(1)]` require these members to be `public`. Get-only properties and properties with a more restrictive setter are still reported
* Parameterless constructors, including explicit parameterless constructors of structs. A public parameterless constructor is required by a `where T : new()` constraint
* Copy constructors of records that are not sealed. The language requires those constructors to be `public` or `protected`. Copy constructors of sealed records and of record structs are still reported
* Members of interfaces (including internal interfaces) and enum members
* Members that are not declared `public`, including implicit public positional properties of records such as `internal record R(int Value)`
* `protected` or `protected internal` members of internal types

This rule is disabled by default because not every team wants to treat `public` on internal types as a problem. Some teams use `public` on internal types to mark members they intend to promote later.

To enable the rule, add this to an `.editorconfig` file:

```ini
dotnet_diagnostic.SA1415.severity = warning
```

## How to fix violations

Change the member's accessibility from `public` to `internal`. The two are equivalent for members of types that are not visible outside the assembly, and `internal` does not appear to be part of the public API. The code fix makes that change only when the resulting code still compiles.

* Partial methods, properties, indexers, and events are updated together. One fix changes every part when each part is editable user code, including parts in other documents. If any part is generated code or is missing from the solution, the diagnostic is still reported and no fix is offered. A partial nested type does not need a second declaration: `public partial class Inner` inside an internal type is changed to `internal`.
* A field or event field that declares several members is updated together with every override of those members. If an override declaration also names another member, that member and its overrides are included in the same fix. When one member of a shared declaration must remain `public`, the declaration is split and only the members that can become `internal` are changed. If a shared declaration cannot be split, or any of the declarations is generated or cannot be edited, no fix is offered.
* When a property or indexer becomes `internal`, an accessor modifier that would no longer be more restrictive is removed. `public int Value { get; internal set; }` becomes `internal int Value { get; set; }`. `private` and `private protected` accessor modifiers are kept. If an accessor is `protected` or `protected internal`, no fix is offered.
* A `virtual` or `abstract` member is still reported. Overrides are not reported on their own, because they must use the same accessibility as the member they override. The fix changes the member and every override in the solution together. If an override is generated or cannot be edited, no fix is offered.

```csharp
internal class Example
{
    public void Method() // SA1415
    {
    }
}
```

```csharp
internal class Example
{
    internal void Method()
    {
    }
}
```

## How to suppress violations

```csharp
[SuppressMessage("StyleCop.CSharp.MaintainabilityRules", "SA1415:DoNotUsePublicOnMembersOfInternalTypes", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1415 // Do not use public on members of internal types
#pragma warning restore SA1415 // Do not use public on members of internal types
```
